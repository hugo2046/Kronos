## 0. 口径锚定（不可偏离，出处：交接说明 §6.1 已确认的论文口径）

- **zero-shot**：官方 `NeoQuasar/Kronos-Tokenizer-base` + `NeoQuasar/Kronos-base` 直接推理，
  **不做任何微调**，Tokenizer 冻结；
- 日频，回看 **L=90 个交易日**，预测 **H=10 个交易日**；
- 信号 = H 日平均预期收益率：`signal_t = mean(pred_close[t+1..t+H]) / close_t - 1`，做**截面排序**；
- 归一化用 `KronosPredictor.predict` 内置逻辑（仅回看窗口 z-score + clip 5，[kronos.py:544](../model/kronos.py:544)），
  **不要自己重写归一化**；`kronos_qlib` 已按此约定不做预归一化；
- 采样参数固定：`T=1.0, top_p=0.9, top_k=0, sample_count=5`（`predict_batch` 内部对 5 次采样取均值），
  全程 `torch.manual_seed(42)`；这些进 config，不许在阶段间漂移。

## 2. 阶段 1：取数与窗口构造（数据层已就绪，本阶段只做接线与体检）

```python
from kronos_qlib import QlibProvider, build_inference_windows
p = QlibProvider("csi300", start, end)
df_list, x_ts, y_ts, codes, stats = build_inference_windows(
    p, rebalance_date, lookback=90, predict_len=10, pool="csi300")
```

**体检门禁**（任一不过即停）：

1. 逐调仓日 `stats["n_pool"]` 应恒为 300（沪深300 定员）；`n_kept` 应 ≥ 280，
   `skipped_halt + skipped_short` 明显异常（如某期 kept < 250）要先查清再继续；
2. **池随时间变化**：抽查首末两个调仓日的成分集合，必须不同（相同即 point-in-time 失效）；
3. 每个 `df` 恰 90 行、列序为 `open/high/low/close/volume/amount`、无 NaN；
4. `x_ts` 末值 == 调仓日（或其之前最近交易日），`y_ts` 恰 10 个交易日且全部 > `x_ts` 末值。

**不要**再做"抽 5 只与公开行情核对"——数据层的复权自洽性已由集成测试验收
（188,400 行中剔除各股首行后最大偏差 1.52e-05）。

## 3. 阶段 2：正确性试点（50 只 × 6 个调仓日）

- **调仓频率**：每 10 个交易日一次（与 H=10 对齐，不重叠）；
- 抽 50 只（seed=42）跑 6 个调仓日的完整链路：构窗 → `predict_batch` → 算 signal；
- **正确性抽查**（逐条贴输出）：
  1. 任取 2 只 1 个调仓日，打印预测 10 日 close 路径与真实路径，确认预测值与
     输入窗口末值同数量级（后复权价常达数百元，反归一化错误会立刻暴露）；
  2. 同一输入连跑两遍（同 seed）信号逐位一致；
  3. signal 全部有限、无 NaN，且其截面分布不是常数（全相等说明预测退化）。

### 3.1 可评估边界（硬门禁，越界即错）

日历延伸到 **2040-12-31**，真实数据止于 **2026-08-07**。`build_inference_windows` 只在
2040 日历用尽时才报错，**不会**替你拦住"预测得出、真实收益取不到"的调仓日。故：

```
最后一个可评估调仓日 = 交易日历中 <= 数据末日 的倒数第 (H+1) 个交易日
```

实测该日为 **2026-07-24**。回测区间取 `2022-01-04 ~ 2026-07-22`，
每 10 个交易日一个调仓日，共 **111 期**（实测）。

**门禁**：全量运行前必须打印「数据末日 / 最后可评估调仓日 / 实际调仓日数 / 首末调仓日」四项，
且断言最后一个调仓日 + H 个交易日 ≤ 数据末日。缺这一步的结果一律不采信。

## 4. 阶段 3：全量信号生成

- 沪深300 全池，区间与调仓日按 §3.1 确定（111 期）；
- 产出 `cross_section/data/signals.parquet`：`date, code, signal, fwd_ret_10d`
  （前向收益 = `close[t+10]/close[t] - 1`，后复权 close-to-close，与信号同源）；
- **无未来函数自查**：信号只用 ≤ t 的数据；`fwd_ret` 只用于事后评估，绝不回流入信号。
  数据层已保证窗口截止 `t`，但**你自己算 `fwd_ret` 的那段代码没人替你把关**，
  必须单独写一个断言：构造 signal 用的最大日期 ≤ 调仓日；
- 调仓日 t 的可交易性（涨跌停、停牌次日复牌）首轮不建模，记录为局限。

## 5. 阶段 4：因子评估（方法论调用 `factor-evaluation` skill）

对 signal 做标准单因子检验，**同时对基线因子跑完全相同的评估代码**：

- **基线**（同口径同池同调仓日，成本几乎为零）：
  1. 10 日动量：`close[t]/close[t-10] - 1`；
  2. 10 日反转：动量取负（A 股日频反转通常更强，这是 Kronos 必须跨过的真实门槛）；
- **指标**：
  1. 逐调仓日 RankIC → 均值、ICIR、t 值（111 期，t 值可参考但要标注样本量）；
  2. 分 5 组等权，组合收益单调性 + 多空（Q5-Q1）每期收益、累计净值、年化与最大回撤；
  3. 多空收益扣除单边 15bp 近似成本后的净值（每 10 日双边换手上限 200%，粗算即可）。

## 6. 阶段 5：判读（预注册，先否决项）

1. **信号存在性**：|RankIC 均值| < 0.02 或 |ICIR| < 0.3 → 结论"zero-shot 无可用截面信号"，
   停止，不做任何参数搜索（111 期样本上调参必然过拟合）。IC 为负也算有信号（反转性），
   如实记录方向；
2. **相对基线**：Kronos 信号的 |RankIC| 与多空净值**未同时超过**动量、反转两条基线中较强者 →
   结论"信号存在但不优于免费价量因子，zero-shot 路线无增量价值"；
3. 两关都过 → 结论"zero-shot 截面信号成立"，下一步才谈 A 股微调增强（另立计划）；
4. 与东证报告的对应结论互相印证/冲突之处，用 `notebooklm` skill 查询笔记本
   `kronos论文与a股落地分析` 核对后写入文档，不许凭记忆复述报告数字。
