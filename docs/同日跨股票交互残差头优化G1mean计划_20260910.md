# 同日跨股票交互残差头：优化 G1 mean 的最小实验

> 执行者Debian zcode使用using-superpowers / executing-plans，按checkbox执行。用户在全分支去重复核后同意此方向；本轮研究预测结构，不转去选seed、组合择时或120日前向观察。

**目标：** 在冻结G1的基础上，检验预测某只股票时引入同日其他股票的历史表示，能否在当前固定Qlib口径下超过G1 mean，并优于关闭股票间交互的同构残差头。

**架构：** 一个交易日作为一个集合，输入`[batch_days,n_stocks,D]`；用小型非因果集合attention产生每股残差，最终`signal=原G1 mean+残差`。OFF/ON两臂结构与参数形状相同，仅attention是否能访问其他股票不同。原G1的时间主干、tokenizer和输出头全部冻结。

**技术栈：** Python3.10+、PyTorch、pandas/numpy、Qlib/R、matplotlib、pytest、loguru；Path、严格类型注解、公共Sphinx docstring、中文关键注释。

## 2. 三臂固定，唯一实验变量是交互掩码

| 名称 | 输出 | attention规则 |
|---|---|---|
| G1_mean | 原FULL G1缓存，不重推 | 原基线 |
| PEER_OFF_s | G1_mean + σe·r_OFF | 只允许每个股票token关注自己（对角掩码） |
| PEER_ON_s | G1_mean + σe·r_ON | 同日全部有效股票互相可见 |

两臂同seed、同初始参数字节、同数据/样本键/批次顺序、同loss/优化器/预算。OFF的Q/K由于对角attention可能没有有效梯度，这是交互消融的自然结果；不能虚称两臂每个参数梯度相同或有效容量完全相等。

先seed100；只有至少一个新头两窗都胜G1才补101/102，两臂同时补，不只补赢家。所有seed完整展示，不改结构或权重。

## 3. 输入、peer集合与监督集合严格分开

### 3.1 固定底座与每股隐状态

- 原G1 tokenizer/predictor全部eval、requires_grad=False、no_grad。底座SHA与既有SAE实验相同，先核对本机真实文件身份。
- 每股历史输入截至t的90个交易日OHLCVA，窗口归一化/clip5/时间特征与G1相同；用`KronosFrozenBackbone.extract(...)[:,-1,:]`得到原始h，预期D=832。
- 只缓存最后一步h，不重复储存90步隐状态，不把未来bar输入tokenizer。任何日期t之后行情变动不得改变t的历史窗口或h。

### 3.2 PeerSet（决定模型能看到谁）

`PeerSet(t)=t日csi300 PIT成员 ∩ 截至t具有合格90日历史输入的股票`。

peer资格**不能使用**未来收益、未来停牌、未来退池或标签完整性。构造PeerSet只读截至t的数据；标签生成是完全独立的后续步骤。未被监督的股票仍可参与attention，为其他股票提供当时可见信息。

- 训练、验证、测试均采用同一PeerSet规则；不在训练时用随机64股作全部context、测试时改为300股。
- 每个日期保存完整peer键、资格/排除原因、历史窗口边界、source快照/版本。股票排列统一按code排序仅用于确定性存储；模型不允许依赖这个顺序。
- 测试可评分集合保持原G1有效格；每个基线格必须有对应h与输出。PeerSet中若有额外历史合格但原G1无信号的股票，可仅作为context，必须记录额外数目，不能新增为交易候选。基线格不属于PeerSet时停止排查，不悄悄缩池。

### 3.3 LossSet（哪些股票提供监督）

为隔离新机制并节省昂贵teacher生成，本轮**固定复用SAE已冻结的监督样本键与残差标签**：train 534日期×64=34,176条，val22日期×64=1,408条；原train截至2024-12-31，val截至2025-06-30，每5交易日采样规则不改。

- 原SAE每日期64股仅为LossSet，不是PeerSet。所有原LossSet键必须是本轮PeerSet的子集；缺失不能静默替换别股。
- `y_mean=mean(close[t+1..t+10])/close[t]-1`；`e=y_mean-s_G1`；训练目标`r=e/σe`，不减残差均值；输出修正还原`σe*r_hat`。
- s_G1和y_mean使用原SAE train/val缓存原值；不按新head seed重推teacher。它们来自原G1训练内残差，仍披露in-sample及验证期与G1旧验证期重叠的限制。
- 标签完整性只影响LossSet/损失mask，不能反向删除PeerSet中的股票；扰动或清空某股未来标签时，同日所有股票的forward必须不变。
- μh/σh/σe直接复用`f6c0726`保存的训练期`norm_stats.json`（σe约0.0490884），先校验原文件与缓存SHA。OFF/ON同用，不能在全peer或测试段重新fit统计。

这样本轮OFF/ON使用相同的已知监督任务，仅增加/屏蔽同日peer信息；不因追求更好收益扩大样本或换目标。与SAE结果的差异不是单纯attention因果证据，真正的机制对照是本轮ON−OFF。

## 5. 冻结结构与训练超参

原始h按冻结SAE统计标准化：`x=(h-μh)/σh`。小头结构如下，OFF/ON完全同形状：

```text
x[D] → Linear(D,64) → u
v = LayerNorm(u)
a = MultiheadAttention(64,4,dropout=0,batch_first=True)(v,v,v,mask)
z = u + a
z = z + Linear(128,64)(GELU(Linear(64,128)(LayerNorm(z))))
r_hat = Linear(64,1)(LayerNorm(z))
```

最后Linear的weight/bias全0初始化；无股票位置embedding、无行业embedding、无BatchNorm、无额外dropout。LayerNorm只沿每个股票的特征维。股票维不使用因果三角mask；OFF仅对角可见，ON同日有效peer全可见。padding股票从key/value和loss中屏蔽，padding内容不得影响真实输出。

每个batch最多4个日期，按max N padding，日期维是batch而非attention序列。严禁把4天拼成一个N轴。PyTorch MultiheadAttention的布尔mask中True表示禁止访问；按此语义测试OFF对角可见、ON有效股全可见。OFF的padding query不能被遮成全行无合法key（会产生NaN及梯度污染）：可将这些废弃query临时只连该日首个有效key，再把其输出置零；所有有效query仍只看自己。全padding日期拒绝输入。预期总参数约8.7万，实际构造前列参数表与精确数目；不因表现不好改维数/层数。

| 项目 | 固定值 |
|---|---|
| 数据与目标 | §3固定LossSet；每日期在被监督股票上计算mean MSE，再对batch日期等权mean |
| optimizer | AdamW lr3e-4、betas(0.9,0.999)、wd0.01、clip_grad_norm3 |
| 预算 | 100epochs，全部冻结训练日期每epoch遍历一次；batch_days4，尾batch照常，FP32；无early-stop/scheduler |
| seed | 100，条件确认101/102；OFF/ON成对同初始化和日期shuffle |
| 唯一选点 | 验证日等权预测MSE最低epoch，严格更低才更新，并列最早；不看收益/RankIC选点 |
| 模型状态 | G1恒eval/no_grad；新头训练后独立eval；最后残差零初始化为实现门禁 |

OFF虽然保留全部peer输入，但只能看到自己，因此无需特殊缩batch；ON和OFF同用相同输入tensor、padding与LossSet。模型不能接收label、label-valid标志或样本是否被监督作为特征。
