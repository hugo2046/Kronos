## 2. 阶段 G3：前瞻信号登记（种子诊断判读后立即启动，长期运行）

**目的**：把 forward 验证从事后回测升级为事前登记——信号在结果发生前落盘并
git 盖章，2026-11 结算时具备实盘级前瞻证据等级。

**登记内容（每个交易日收盘后）**：
1. G1 三种子（100/101/102）四变体当日 csi300 截面信号（S3 降级不影响登记，只影响措辞）；
2. M 动量信号 + MA200 门控状态（R1 切换的前瞻记录，一并结算）；
3. 当日 csi300 成分与可交易掩码快照（结算时免受后视成分调整污染）。

**机制（冻结）**：
- 新建 `finetune_suite/run_registry.py --date auto`：幂等（重复运行同日不重复追加）、
  只用截至决策日的数据（断言当日 K 线已收盘）、逐日落盘
  `finetune_suite/registry/signals_<date>.parquet` + DuckDB `registry` 表；
- **git 盖章**：每日运行后将当日 parquet 的 SHA256 写入
  `finetune_suite/registry/MANIFEST.csv`（date, file, sha256, n_stocks, created_utc）
  并提交推送——**manifest 入库，parquet 不入库**；提交时间戳即事前证明；
- 生产机 cron：每交易日 16:30 CST 运行（含节假日跳过逻辑），失败时次日补跑并在
  manifest 标注 `late=true`（迟补的日期在结算时单独列示）；
- **零判读纪律**：登记期间不计算任何绩效、不出图、不看收益——登记只写不读；
  结算判据在 2026-11 结算计划中另行跑前冻结。

**步骤**：
- [ ] G3.1 `run_registry.py` + `test_registry_idempotent`（同日重跑不重复）、
  `test_registry_no_lookahead`（构造次日数据不影响当日信号）→ 先 FAIL 后 PASS；
- [ ] G3.2 首日手动运行 + manifest 首条提交（贴输出）；cron 安装并贴 crontab 行；
- [ ] G3.3 提交推送（`feat(finetune_ashares): G3前瞻登记上线`）。
