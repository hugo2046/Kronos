# PEER 生产身份接线修复（20260910）

本次基于 `61d2df4` 补齐实际训练、推理、缓存读取和冻结回测入口的身份校验。此前新增的独立身份函数虽有测试，生产 `train_arm → load_best → infer_test_signal` 仍走旧 schema，复用失败还会自动重训；冻结回测仅检查信号文件 SHA，未核验身份字段。这些遗漏已通过生产入口测试复现并修复。

## 行为变化

1. `train_arm` 保存新 identity 和每个 epoch 的文件 SHA；`load_best/load_head` 必须同时匹配当前协议、底座、SAE/peer 清单、归一化统计、arm/seed/epoch 和权重 SHA。旧 schema 不自动转换，历史诊断仍使用单独的精确 SHA legacy 路径。
2. `_train_missing` 先检查所有已有头，任一身份不符立即停止；没有 best 清单但存在中断权重也停止。不会先训练另一臂，或用重训覆盖失败的旧资产。直接调用 `train_arm` 同样拒绝覆盖已有同臂同种子产物。
3. `load_split_days` 在读取、装配任何实际样本前检查缓存清单的精确键集合和逐 chunk 字节 SHA，避免“清单 SHA 没变但缓存文件变了”的绕过。
4. 冻结阶段先验证所有头，再生成、保存全部信号，连同 G1 基线快照和头文件归档，最后校验后写完成清单；既有冻结清单及信号禁止覆盖。
5. 回测入口逐项核验当前协议/run/base/cache/norm 身份、基线来源及快照、每个头和每份信号；缺失、多余、重复臂窗、错误网格或 SHA 不符均在调用回测器前拒绝。回测读取已经核验的内存快照，包含 G1，避免检查后又从其他文件重新读取。

## 验证

- 新增生产接线测试先失败后通过：缺 identity、复用失败进入训练、错误 run/protocol/base/head/cache 元数据仍进入回测、重复冻结覆盖、缓存字节变化未被拒绝、中断权重未阻止其他臂启动。
- 旧两 epoch 最佳权重测试改用合成完整身份；旧冻结顺序测试仍验证真实编排，增加合成头文件与基线快照，未移除原断言。
- 组合测试 **75 passed**：`test_peer_residual.py`、`test_peer_diagnostic.py`、`test_peer_production_gates.py`、`test_qlib_mean_comparison.py`、`test_sae_residual.py`。
- 全部使用合成 CPU 数据；测试中的一至两 epoch 极小头更新只用于验证保存/加载接线。未进行真实实验训练、G1 推理、GPU 运算、数据库查询、历史回测或 forward 读取。
- 原交接清单 39 件资产逐项 SHA 不变，`peer_diagnostic_20260910/` 的样本、诊断、图片及历史纠偏摘要未修改。
