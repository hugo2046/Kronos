# Kronos 方向分类头改造方案

> 日期：2026-08-09
> 分支：`feature/direction-classifier`
> 来源：小红书作者 wiw 的实践分享——"改网络结构，加分类器，从头训练"；"加在 predictor 的 TransformerBlock 后面，回归部分删除了"；"我没用原版 Kronos 的 Tokenizer，也不需要预训练了"。评论区另有关键质疑："考虑了未来函数吗"。

## 1. 背景与动机

原版 Kronos 是**生成式**架构，链路为：

```
OHLCV → KronosTokenizer (BSQ 量化 → 离散 token) → Kronos Predictor (自回归下一 token 预测) → 解码回价格序列
```

- Predictor（`model/kronos.py:180`）：`HierarchicalEmbedding(s1,s2 token)` + `TemporalEmbedding` → N×`TransformerBlock` → `RMSNorm` → `DualHead`（s1 logits）→ `DependencyAwareLayer` → s2 logits（`model/kronos.py:254-276`）。
- 训练目标是离散 token 的交叉熵，推理靠 `auto_regressive_inference` 采样再解码。

若下游任务只是**方向判断**（涨/平/跌），生成完整价格路径是绕远路：

1. 两阶段训练（Tokenizer + Predictor）成本高，且 Tokenizer 量化引入信息损失；
2. 自回归采样有随机性，方向信号要靠多次采样平均才稳定；
3. 此前 loss 分析（2026-08）已确认：离散 token 交叉熵与连续金融目标（PnL/Sharpe 等）天然不兼容，分类头直接绕开该问题。

wiw 的思路即把 Kronos 降维为**判别式**模型：删掉 Tokenizer 与生成头，只保留 Transformer 主干 + 分类头，端到端从头训练。删掉 Tokenizer 后原预训练权重（绑定在 token 词表上）无法迁移，故"从头训练"是必然结果而非额外选择。

## 2. 目标架构

```
连续 OHLCV+amount (归一化) ──► nn.Linear(6, d_model)  ┐
时间戳特征 ────────────────► TemporalEmbedding        ├─(相加)─► N × TransformerBlock ─► RMSNorm ─► 取最后时间步 ─► Linear(d_model, 3) ─► CE loss
                                                      ┘
```

复用与删除对照：

| 组件 | 处置 |
|------|------|
| `TransformerBlock` / `RMSNorm` / `TemporalEmbedding`（`model/module.py`） | **复用** |
| `KronosTokenizer` / `BSQuantizer` | **不使用**（连续输入直接线性投影，写法参考 `KronosTokenizer.embed`，`model/kronos.py:56`） |
| `HierarchicalEmbedding` / `DualHead` / `DependencyAwareLayer` | **删除**（不引入新模型） |
| 预训练权重 | **不加载**，Xavier 从头初始化（复用 `_init_weights` 写法） |

**注意：不修改 `model/kronos.py` 现有类**，新模型独立成文件，保证原生成式链路不受影响。

## 3. 实施内容

### 3.1 新增 `model/kronos_classifier.py`

```python
class KronosClassifier(nn.Module):
    """判别式方向分类模型：Transformer 主干 + 分类头，从头训练。

    :param d_in: 输入特征维度（默认 6：OHLCV + amount）
    :param d_model: 模型隐层维度
    :param n_heads: 注意力头数
    :param ff_dim: FFN 维度
    :param n_layers: TransformerBlock 层数
    :param n_classes: 分类数（默认 3：跌/平/涨）
    :param learn_te: 是否使用可学习时间嵌入
    """
```

- forward：`x = embed(features) + time_emb(stamp)` → dropout → N×block → norm → **取最后一个时间步** `x[:, -1]` → `Linear(d_model, n_classes)` 输出 logits。
- 默认超参从小起步防过拟合：`n_layers=4, d_model=128, n_heads=4, ff_dim=256`，dropout 0.1。
- 在 `model/__init__.py` 导出。

### 3.2 新增 `finetune_csv/dataset_classification.py`

新建 `KlineClassificationDataset`（参考 `CustomKlineDataset`，`finetune_csv/finetune_base_model.py:25`，但不要直接继承后打补丁，独立实现更清晰）：

- 特征窗：`[t-L+1, t]`（L=lookback_window，默认 90）。
- 标签：`r = close[t+H] / close[t] - 1`（H=predict_window，默认 10），按阈值分 3 类：
  - 阈值 `±θ` 取**训练集** `r` 分布的 30/70 分位数（类别近似均衡），估计后冻结并透传给 val/test；
  - 也支持固定阈值（如 ±0.5%）作为可配置备选。
- 划分沿用现有按时间顺序 70/15/15。

**未来函数防护（本方案的硬性验收项）**：

1. 现有 `CustomKlineDataset.__getitem__` 的 z-score 用了**整个 window（lookback+predict）的均值方差**（`finetune_base_model.py:125-127`），未来 K 线泄露进了特征归一化。新数据集必须**只用 lookback 段**计算 mean/std；
2. 分位数阈值只在训练集估计；
3. 特征列不得包含 `t` 之后的任何行。

### 3.3 新增 `finetune_csv/train_classifier.py`

单阶段训练（对比原两阶段 `train_sequential.py` 大幅简化）：

- 损失：`nn.CrossEntropyLoss(weight=class_weights)`，class_weights 按训练集类别频率倒数；
- 优化：AdamW + OneCycleLR（沿用 `finetune_tokenizer.py:159-172` 的写法与超参风格），梯度裁剪 max_norm=2.0；
- 早停/选模型：按 **val macro-F1**（不是 accuracy，防止全预测多数类）；
- 配置并入 `finetune_csv/config_loader.py` 现有机制，新增 classifier 段。

### 3.4 评估（写入训练脚本的 test 阶段）

- 分类口径：accuracy、macro-F1、混淆矩阵；
- 金融口径：按预测方向构造简单多空（预测涨做多、跌做空、平空仓）在 test 段的累计收益与胜率；
- **两条必须战胜的基线**：① 多数类基线；② 动量基线 `sign(close[t]/close[t-H] - 1)`。战胜不了基线说明模型没学到东西，不要上报好看的 accuracy。

### 3.5 新增 `tests/test_kronos_classifier.py`

1. 前向 shape 测试：`(B, L, 6)` + `(B, L, 5)` stamp → `(B, 3)` logits；
2. **无未来函数构造性测试**：同一样本，篡改 `t+1` 之后所有行的数据，特征张量与归一化结果必须逐位不变；
3. 标签正确性：手工构造已知收益率序列，验证分箱结果；
4. 训练冒烟测试:随机数据跑 2 个 epoch，loss 下降且无 NaN。

## 4. 实施步骤（供执行方按序推进）

```
1. model/kronos_classifier.py + __init__.py 导出  → 验证：tests 前向 shape 通过
2. dataset_classification.py                      → 验证：无未来函数测试 + 标签测试通过
3. train_classifier.py + config                   → 验证：冒烟测试通过（finetune_csv/data 下样例 CSV 跑通）
4. 评估与基线对比                                  → 验证：输出混淆矩阵 + 两基线对比表
```

### 4.1 本机运行环境（Mac MPS，已实测）

2026-08-09 在本机实测：方案模型结构（0.68M 参数）在 MPS 上前向+反向正常，20 个 train step（batch=32, L=90）仅 0.43s，全量训练与验收步骤均可在本机完成。执行方注意三点：

1. **设备选择**：现有脚本硬编码 `cuda if available else cpu`（`finetune_base_model.py:375`），`train_classifier.py` 必须写成 `cuda → mps → cpu` 三级回退（`torch.backends.mps.is_available()`）；DDP 分支在 MPS 下跳过；
2. **依赖**：`einops` 需按 requirements.txt 安装（本机 miniconda 环境已装）；
3. **libomp 冲突**：本机存在 OpenMP 重复链接问题，运行需 `KMP_DUPLICATE_LIB_OK=TRUE`（仅本机 workaround，不要写进代码）；
4. RoPE 为实数 cos/sin 实现（`model/module.py:297`），无复数算子，MPS 兼容无忧；方案 B 冻结主干（Kronos_base 约 97.5M）仅前向推理，MPS 同样可行。

## 5. 风险与开放问题

- **过拟合**：单标的 CSV 从头训练数据量有限（wiw 场景可能是全市场数据）。缓解：小模型、dropout、早停；后续可扩多标的合并训练。
- **"平"类定义敏感**：阈值选取直接影响类别分布与可学性，先用分位数方案，固定阈值留作消融。
- **窗口归一化尺度**：只用 lookback 段归一化后，价格类特征仍非平稳，后续可消融"对数收益率化"输入。
- 原 `CustomKlineDataset` 的全窗口归一化对生成式训练同样是泄露，本方案不动它（surgical change），但建议另开 issue 跟进。

## 6. 论文与东方证券报告对照审查（2026-08-09 补充）

> 依据 NotebookLM 笔记本（Kronos 论文 AAAI 2026 + 东方证券《量化研究参考系列之五》+ A股落地分析）审查本方案与本仓库复现，结论如下。

### 6.1 复现偏差确认（repo vs 论文）

| 项目 | 论文规定 | 本仓库现状 |
|------|----------|-----------|
| 窗口归一化 | z-score 统计量**仅在回看窗口**上计算，clip 至 [-5,5] | 官方 `finetune/dataset.py:107` 正确（注释明确 "strictly on the past"）；社区 `finetune_csv` 用**全窗口含未来段** → **复现 bug，非仅本方案顾虑** |
| 下游微调 | 论文评估为 zero-shot，Tokenizer 始终冻结 | `finetune_csv/train_sequential.py` 两阶段均微调（含 Tokenizer），属社区扩展而非论文做法 |
| 日频窗口 | 选股模拟：回看 90 天、预测 10 天，H 日平均预期收益率作因子 | `finetune_csv` 默认 lookback=90 / predict=10，一致 |
| 词表 | k=20 bits，coarse/fine 各 10 bits（子词表 1024） | s1_bits=s2_bits=10 默认值一致 |

### 6.2 方案方向的外部评价（报告观点）

东方证券报告**不建议**"删除 Tokenizer + 从头训练纯判别式"路线，理由：① 金融高噪声环境下直接分类易拟合短期波动；② 丧失 BSQ 量化的天然去噪与极值截断；③ 无法继承 12B K线预训练的通用表征。报告推荐的两条替代路径：

- **生成式 + 蒙特卡洛多路径平均**（原版路线）：信号最稳健，但推理成本高；
- **隐状态提取截面因子**：取预训练主干最后一层表征注入下游选股模型（linear probe / GBDT），高效且保留预训练红利，需二次建模。

另注意：报告的选股场景**不做涨跌平分类**——直接用 H 日平均预期收益率做截面排序 Top-k，无阈值设定先例；分类阈值路线仅适用于 wiw 式的单标的择时场景。

### 6.3 对本方案的修订建议

1. **保留本方案作为实验分支**，但定位降为"轻量判别式基线"，其价值在于验证 wiw 路线与量化推理成本，而非替代生成式主线；
2. **新增对照实验（方案 B，强烈建议）**：加载预训练 Kronos 主干（冻结），在其隐状态上仅训练同一个分类头（linear probe）。若方案 B 显著优于从头训练，即为"预训练红利不可丢"的直接证据，与报告结论互相验证；
3. 过拟合风险由"中"上调为"高"（报告点名从头判别式易拟合噪声），小模型 + 早停 + 基线对比为硬性要求；
4. 后续如转向截面选股场景，应放弃分类标签，改用 H 日平均收益率 + 截面排序（报告口径）。
