# G1 max 与 C1：固定候选的同口径 Qlib 核验

> 执行者Debian zcode使用using-superpowers / executing-plans，按checkbox推进。用户同意基于跨分支审计继续核验G1 max和C1；本轮仅使用历史缓存、零训练零推理零GPU，不读取forward、不改候选定义、不挑seed。

**目标：** 在用户固定的Qlib/FULL/同池同费用口径下，判断两个既有候选是否高于G1 mean，并交付足够的历史数据供Mac独立复算。结果仅作历史候选核验，不认证“无过拟合赢家”。

**架构：** 读取原G1四变体与三seed mean缓存，构造固定G1 max和C1等权集成，用同一Qlib原生策略回测；R管理本轮记录，Parquet/JSON/图表随Git回传。复用现有回测纯函数，不运行任何模型或修改训练代码。

## 2. 候选固定定义

| 主图名称 | 信号 | 说明 |
|---|---|---|
| G1_mean | 原G1 s100 mean，FULL缓存原值 | 用户唯一主基线 |
| G1_max | 同一G1 s100生成链的max缓存 | 20条采样路径既有平均预测close，再在10个预测时间步取max，除close_t减1 |
| C1_mean_ensemble | `(G1_s100_mean+G1_s101_mean+G1_s102_mean)/3` | 平均的是同日同股信号，不是三条策略收益/NAV |

max只涉及模型预测，不使用真实未来最高价；不得把“max”误解为从20条采样路径挑收益最好的一条。C1三个成分缺任一值即无信号（`skipna=False`），不能改成两seed均值或用0补。

主比较基准身份：G1 W3 SHA=`9352b40302eb34c714bfebd808481b625a21d2f7f4f668ccca15cda0cfe21d66`；W4 SHA=`453e2aeae7fe4bee8ce8fa62a9908da0843d5ad8b52777cd3b299a84cc4a3e36`。

## 5. 主比较与不挑结果纪律

固定主口径：`net_daily=report['return']-report['cost']`，`curve=net_daily.cumsum()`。对每窗分别计算 `D_max=curve_max[-1]-curve_mean[-1]`、`D_C1=curve_C1[-1]-curve_mean[-1]`，单位百分点。

- 两窗D均>0 → “当前Qlib历史对照中两窗均超过G1 mean的候选”；一窗正一窗非正 → “跨窗不一致”；两窗均≤0 → “本轮未超过基线”。不要求先跑赢沪深300才能认定相对改善。
- 同时报告相对曲线、差额>0的天数、复利净值/MDD/成本/换手附表，明确cumsum不是复利。
- 主图必须同时展示G1 mean、G1 max、C1，市场参考虚线；下半幅D_max与D_C1及0线，不只画收益高的一条。
- s101/s102单体仅作为C1构造一致性与风险解释的附表，不新增为候选，不将其中最高收益seed命名为“改进版”。
- 禁止追加权重搜索、截断日期、短持有期、不同回测引擎或“max与C1再混合”。没有历史赢家也是有效交付。
- **不输出“已排除过拟合”“已经独立验证”**。本轮选候选已受W3/W4历史影响，后续须在开封前固定小候选族与相对G1指标，用独立未判读数据检验；本轮不执行该检验、不变更现有forward纪律。
