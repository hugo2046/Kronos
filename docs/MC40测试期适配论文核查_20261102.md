# MC40 测试期适配论文核查

2026-11-04补充：A阶段实际schema与接口核查发现历史可用时间和复权版本证据不足，数据前提门禁未通过，详见[A阶段报告](MC40测试期适配A阶段核查报告_20261104.md)。

核查日期：2026-11-02。阶段：原始论文与官方代码核查完成，迁移假设待验证；未训练、未回测、未读取 2026-07-25 以后封存数据。结论是可以借鉴“真实标签到达后，只更新很少参数”的机制，但 PETSA/TAFAS 的预测修订口径不能直接用于 MC40 已发出的十日选股信号，也没有证据表明通用预测 MSE 的改善会带来股票净收益增量。

本轮建议的改动只涉及现有状态适配残差的测试期强度校准；本土化 G1、tokenizer、原自回归生成出口和 seed42/100 各 20 路径等权配置保持既定定义。本文是论文研究备忘录，不是新增模型采纳记录；没有候选收益或累计收益曲线。

## 2026-11-04实施语义补充

首轮迁移的具体规则见[延迟反馈适配方案](MC40延迟反馈适配方案与防泄漏规则_20261104.md)。只读核对远端实现后，需要补强两点。现有窗口构造会先请求至未来第10个交易日再截取历史输入，TTA须在读前增加逐发行时点的as-of限制。原CE前向实际调用`use_teacher_forcing=False`，下文“teacher forcing”是当时的概括，后续实现应遵循原shifted token输入及粗细头开关的确切语义。数据源available_at及复权历史版本仍须在工程门禁中核实。

## 1. 本项目问题与证据边界

任务提供的当前身份是：冻结本土化 G1/tokenizer，在最后两层加入 rank32 动态 adapter，约 107712 个参数，以过去 90 日波动状态作为条件；输出仍来自原自回归生成的未来 10 日预测均价。训练截止 2024-12-31，验证区间为 2025H1；W3/W4 已经反复查看，属于开发窗口，不能重新包装成独立验证。以上身份来自本次任务上下文，本文未核验本地权重 SHA。

旧交易引擎曾将涨跌金额 `change` 错当收益率；今后执行口径是 `pctchange/100`，统一 9.5% 日频限制仍只是研究简化。已提供的纠偏后 MC40 历史领先及静态/动态 2×2 区间跨零，支持继续研究，但不支持“状态机制已获因果证明”。本文不重复旧口径收益，也不据两篇论文为已有负结果翻案。汇报口径遵循[研究汇报规范](研究汇报规范_20261101.md)。

## 2. 两篇论文是什么级别、解决什么问题

| 论文 | 已核验发表身份 | 对本项目最有用的内容 |
|---|---|---|
| TAFAS：Battling the Non-stationarity in Time Series Forecasting via Test-time Adaptation | AAAI 2025 正式会议论文，39(17):17868–17876；不是仅有预印本 | 标签会延迟到达；可用已经观察到的预测前缀更新小校准模块 |
| PETSA：Accurate Parameter-Efficient Test-Time Adaptation for Time Series Forecasting | ICML 2025 第二届 PUT Workshop 接收为 Poster，另有 arXiv v1；不能称 ICML 主会论文 | 将校准矩阵低秩化，并研究稳健/频率/结构损失 |

发表身份分别由 [AAAI 官方出版信息](https://ojs.aaai.org/index.php/AAAI/citationstylelanguage/get/apa?publicationId=32238&submissionId=33965) 与 [PUT 官方接收列表](https://tta-icml2025.github.io/papers.html)确认；论文为 [TAFAS 原文](https://arxiv.org/html/2501.04970v1)和 [PETSA 原文](https://arxiv.org/html/2506.23424v1)。本次没有找到可据以升级 PETSA 为主会论文的原始证据。

两者构成同一条技术路线：TAFAS 提供时间调度与校准框架，PETSA 在此基础上减少校准参数并改损失。因此不应把它们当成两份完全独立的成功证据。

## 3. 标签、更新和旧预测修订的核查

设预测起点为交易时点 `t`，预测长度 `H=10`；`p` 表示已经过去且数据实际可用的观测数。这里必须区分“日期已经过去”和“所需字段已经完成发布”。

| 问题 | 核查结果 | 对 MC40 的含义 |
|---|---|---|
| 是否不需要标签？ | 两篇都用真实时间序列观测，不是伪标签或纯无监督熵最小化 | 测试期适配实质上具有延迟监督；不可在 `t` 使用 `t+1…t+10` |
| 部分标签何时可用？ | 到 `t+p` 才能使用第一批 `p` 个已发生值；TAFAS 用输入历史的主周期设置等待长度 | “提前适配”只是比等完整窗口更早，不是预测发出时就有未来前缀 |
| 完整标签何时可用？ | 到整个预测窗口结束后；官方实现还等待该历史 mini-batch 最后一个起点的窗口成熟 | 成熟条件须按实际目标结束时间计算，不能只看输入日期 |
| 更新什么？ | 冻结源预测器，更新输入/输出校准模块；PETSA 将时间变换低秩化 | 当前 MC40 已有参数高效结构，新增价值主要来自在线反馈，而非再加一个 LoRA 名称 |
| 是否修改旧预测？ | TAFAS 明确有 Prediction Adjustment：更新后替换旧起点预测中尚未发生的尾部 | 可以作为“当下发布的新修订版本”，不能回填旧时点交易信号 |

标签与调度见 [TAFAS 的 O1/O2、PAAS 和公式 4–7](https://arxiv.org/html/2501.04970v1#S4)；PETSA 继承部分/完整标签框架，见[方法第 3 节](https://arxiv.org/html/2506.23424v1#S3)。TAFAS 使用 MSE；PETSA 论文组合 Huber、频域和局部结构项。原文的门控/低秩校准并不是“根据 A 股过去 90 日波动状态生成权重”的 MC40 机制，二者同名为动态不能当作机制等价。

### 为什么预测修订不是可直接复制的股票回测技巧

这是本文对本项目的推论：假设周一收盘发布未来十日均价信号，周四才观察到前三日走势。周四可以更新模型并发出周四的新信号；也可以单独发布带周四时间戳的剩余期限修订预测。但是，不能拿周四修订后的尾部重新计算“周一的十日均价”，再用它选择周二买入的股票。这会把后到信息写回旧决策。

因此，论文允许的滚动修订并不必然违反其自身任务的因果关系，但其最终 MSE 与“所有十日预测在发行时锁定”的 MSE 不是同一评估对象。论文收益也不能被解释成固定持仓信号的可交易增量。对于 MC40，所有原信号、路径和权重时间戳必须只追加，不允许覆盖历史版本。

## 4. 官方代码带来的补充与局限

核查的公开版本分别为 PETSA 的初始提交 `87853d888e98311ac94e64be920d17b57143b20c` 和 TAFAS 的初始提交 `139bf980671da4daad728a0fc21d8df508b9203d`。提交入口见 [PETSA 历史](https://github.com/BorealisAI/PETSA/commits/main/)与 [TAFAS 提交](https://github.com/kimanki/TAFAS/commit/139bf980671da4daad728a0fc21d8df508b9203d)。这是源码静态核查，未执行作者程序。

- 两者都在 `cur_step` 达到历史批次预测终点后做完整标签更新，部分标签损失取当前批次第一个样本的前缀。预测修订方法会重算并替换旧起点预测尾部；实现循环未覆盖批次最后一个样本。因此不能把论文表述当成实现完全一致的保证。[TAFAS 官方适配实现](https://github.com/kimanki/TAFAS/blob/139bf980671da4daad728a0fc21d8df508b9203d/tta/tafas.py#L191-L242)
- PETSA 配置默认只选 `cali`，默认开启 `ADJUST_PRED`；默认 rank 为 16。这也说明不能以作者摘要中“全模型更新代价大”的概括，误称 TAFAS 主方案更新全底座。[PETSA 官方配置](https://github.com/BorealisAI/PETSA/blob/87853d888e98311ac94e64be920d17b57143b20c/config.py#L80-L114)
- PETSA 完整标签 FFT 对 `[B,H,C]` 的 `dim=1` 操作；部分标签已切为 `[p,C]`，却仍用 `dim=1`，此时对应变量轴。其所谓结构项用展平相关、均值及 `softmax→kl_div` 实现，未见该函数内显式 patch 切分。这些是论文—代码对应需要澄清的地方，不能直接复制成“已验证的时间频率损失”。[PETSA 官方损失与修订实现](https://github.com/BorealisAI/PETSA/blob/87853d888e98311ac94e64be920d17b57143b20c/tta/petsa.py#L227-L288)

上述实现差异限制可复现性判断，不等于本次已经证明论文所有实验结论无效。本文也没有运行软件来确认数值后果。

## 5. 从连续校准到离散自回归 Kronos，中间缺了什么

TAFAS 原文 Table 3 **确实测试了 Chronos-small/base/large**，在 ETT、`H=96` 上报告结果。因此不能说它完全没有离散生成型时序基础模型的证据。不过，本次查看的作者 [models 目录](https://github.com/kimanki/TAFAS/tree/master/models)和[公开 forecast 入口](https://github.com/kimanki/TAFAS/blob/139bf980671da4daad728a0fc21d8df508b9203d/models/forecast.py)没有找到 Chronos 专用适配路径；量化、采样和梯度如何连接仍不能从这些代码核实。[TAFAS 原文 Table 3](https://arxiv.org/html/2501.04970v1#S5.T3)

以下是针对任务给定 MC40 架构的迁移判断，而不是作者已验证的结论。

1. **输入校准存在离散边界。** 原始数值经 tokenizer 量化后形成 token，不能假定数值校准器可通过离散编码获得普通连续梯度；硬采样的 OHLC 路径也不能直接承担任意 MSE 反传。即使底座权重冻结，输入可微性仍然是问题。
2. **已有 adapter 内部适配更自然。** 保留现有 teacher-forcing token 交叉熵，只调整既有残差分支上的少量参数，可以避免以 sampled 路径构造伪可微训练图。该目标与最终十日均价排名仍不完全一致，必须经济检验。
3. **输出校准虽可微，但未必有交易作用。** 在已生成数值路径后接小校准器不需要穿过采样反传。不过，如果只是给所有股票的最终信号施加同一个正斜率仿射变换，横截面排名可能完全不变；不能看到预测误差变小就认定选股提升。
4. **短周期与周期性先验差异大。** 论文多用 96–720 步预测，十个交易日给频率和 patch 结构的有效样本很少。A 股日频的主周期是否足够稳定并无本文证据，首轮不引入 PAAS/FFT/patch 损失，避免把三个未知因素一起塞进实验。
5. **部分 token 标签也需要可用性审计。** 若 tokenizer 或预处理对一个窗口做非因果混合，刚发生一天的价格并不自动意味着该天最终 token 标签已可获得。首轮等完整十日目标成熟，比未经核查地做逐日 token 更新更稳妥。

## 6. 唯一建议的最小迁移假设

**可检验假设：在 MC40 已有两层状态适配残差上各增加一个在线强度标量，仅以成熟的真实 token 标签校准它们，能够修正阶段性“适配过强/过弱”，并在不改写旧信号的条件下提高未来发行信号的净收益。**

这是假设，不是已观测事实，也不是 PETSA 原样复现。它借鉴的只有“冻结主体、小参数、延迟真实反馈”。

令原第 `l` 层残差为 `Δ_l(h,s)`，候选为 `h + a_l·Δ_l(h,s)`，两层各一个 `a_l`，初值均为 1。G1、tokenizer、现有约 107712 个 adapter 参数均冻结，只学习两个标量；原 checkpoint 本身不被覆盖。标量约束、学习率、一次更新使用的成熟样本数和优化器状态延续规则需在查看结果前写入方案并锁定；首轮不同时搜索更多参数组合。

### 严格因果的更新顺序

1. 在发行时点 `t`，只使用 `available_at ≤ t` 的行情和状态。对某历史起点 `u`，只有完整十日目标、目标涉及的预处理依赖及 tokenizer 编码所需数据均已实际可用，才允许加入更新集。判断使用目标结束与数据可用时间，而非简单 `u ≤ t-10` 日历天。
2. 使用历史起点 `u` 当时的输入窗口、过去 90 日状态和归一化定义，做 teacher forcing；不把 `t` 的状态或包含后续信息的统计量替换到 `u` 上。每次更新后得到 `a_t`。
3. 用 `a_t` 对当前起点 `t` 正常生成 seed42/100 各 20 条路径，按既定方式汇总十日均价，记录模型版本与发行时间，形成此后才允许交易的信号。
4. 后续反馈只能改变 `t+1` 等新起点的参数与信号。旧 `t` 的信号/路径哈希保持不变；`ADJUST_PRED` 式旧尾部覆盖完全禁用。

先做完整成熟标签，意味着放弃论文利用前缀缩短延迟的部分优势，但可以独立回答“很少在线参数有没有增量”。若无效，停止这一轮，不追加 FFT、复杂 gating 或更多在线层来追逐 W3/W4。

### 最小对照与否证条件

- **主基准：原 G1。现行对照：状态适配 MC40（两个标量恒为 1）。候选：同一 MC40 加因果在线两标量。** 生成路径预算、发行/成交时间、资格池、组合、费用与纠偏引擎一致。新参数不计入原 MC40 身份。
- 先验证 `a=1` 时输出与原流程一致、未来标签扰动不影响此前任何参数/信号、旧发行记录不可变、底座和 adapter 参数哈希不变、训练梯度只落到两个标量；这比先看收益更重要。
- 2025H1 只可按既定开发用途固定极少超参；W3/W4 只能作已查看历史的诊断。2026-07-25 后数据继续封存，本文不授权打开。真正独立验证需以后单独批准预注册的一次性方案。
- 经济终点按本项目扣费日收益累加，并同时检查相对原 G1、相对 MC40 的变化、换手和最大回撤。考虑十日目标重叠，应使用时间块置信区间；重复查看历史的选择偏差单独披露。
- 若仅 token 损失下降、排名不变或收益差置信区间仍跨零，不能宣称适配有稳定经济增量。若只在 W3/W4 一窗改善而另一窗恶化，也不能据此采纳。
- 若在线臂出现可信增量，下一轮才需要离线固定强度控制来分离“新自由度”和“在线反馈”；首轮结果本身仍不能建立状态机制的因果结论。

## 7. 与 G8、蒸馏头和此前尝试的差别

| 维度 | 既有 G8（任务给定为全参数更新） | 既有监督/蒸馏头路线 | 本文两标量假设 |
|---|---|---|---|
| 可变部分 | 全模型参数；具体历史训练协议本文未另行核验 | 另建确定性预测出口或学习教师输出 | 两层已有状态残差的两个强度参数 |
| 新监督来源 | 取决于原 G8 协议，不能凭名称推断 | 监督目标或教师预测 | 发行之后实际到达、且完整成熟的真实 token |
| 推理出口 | 应按原 G8 定义核对 | 通常改变生成式出口 | 保留原自回归生成和 MC40 路径汇总 |
| 核心待验证因素 | 大容量更新是否有用 | 表征/蒸馏能否转成稳定信号 | 很少在线自由度是否能校准当前适配强度 |

因此，先前全参数微调、LoRA 或蒸馏失败，并不能逻辑上否决严格因果的小参数在线反馈；同样，换成 TTA 名称也不能免除已有负结果约束。此方案不改变日期权重、不做全局波动削仓，不把此前 D、cap_vol 的问题混进新假设。

本方向的预期价值是用很小实验回答一个尚未被“离线训好后固定”覆盖的问题，而不是凭论文保证可以超过现行 MC40。
