## 4. 既有采集设施审查（只读，不启用不修改）

现有 cron `30 16 * * 1-5 → finetune_suite/run_registry.py --date auto`
（2026-08-14 起运行）与协议 §4 的语义匹配度：

- **身份匹配**：`SEED_MODEL_PATHS` 的 s100/s102 即上表两份 predictor，
  tokenizer 同一 `finetune_tokenizer_g1`；`VARIANTS` 含 mean——两臂
  信号可直接取其 s100/s102 mean 列。
- **时序匹配**：provider 取数边界恒 `end=决策日`、以指数当日有收盘价
  断言 K 线已收盘、幂等（指纹不一致报错拒绝重生成）、迟补标 `late`、
  首日只登最新日不回填、MANIFEST git 盖章；登记器零判读（不计算绩效）。
- **发现的缺口（启动条件，本轮不修）**：
  1. 登记只绑信号文件 SHA，未绑权重/tokenizer/代码/推理 seed 身份；
  2. **登记提交跟随主工作树当前检出分支**：2026-09-07/09-08 两行
     manifest 提交（`dda5796`/`6903304`）落在
     `codex/timesfm-multihorizon`，本分支 MANIFEST 止于 09-04——启动前
     须固定登记分支并跨分支核对全序列（`git log --all --grep=登记前瞻信号`）；
  3. 带日期门禁的评价入口（门禁未满足时**拒绝加载**收益）尚未实现。
