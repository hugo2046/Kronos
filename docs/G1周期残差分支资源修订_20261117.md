# G1周期残差分支资源修订

2026-11-17。正式训练前，root依据A阶段实测作出资源执行决策：将GPU硬上限从默认12小时调整为14小时（50400秒），墙钟硬上限保持16小时（57600秒）。科学配置不变；本次源码修订不代表新门禁已通过，须等待root独立审查、预算重评和新gate签署后才能启动训练。

## 决策依据与授权表述

用户授权我们定方案并在门禁后完成两臂训练和完整回测。12小时是root自设的默认规划值。A实测保守估计剩余GPU约47426.96秒，加已累计814.536823秒，总计约48241.50秒，即13.4004小时，超过原12小时规划值。root已向用户说明，据此在正式训练之前把GPU硬cap修订为14小时，继续保留16小时墙钟和资源守卫。

这是root基于既有任务授权作出的执行决策，不能表述为“用户明确批准14小时”。修订不依据收益、IC或验证效果，不改变任何科学配置，也不将旧12小时预算失败改写为通过。

## 唯一变更与不变边界

- GPU硬上限：43200秒改为50400秒。`runtime.freeze`协议字段、`runtime.exhausted`耗尽判据、`train.require_A`开训预算检查、`pilot`可行性判据同步修改。
- 墙钟硬上限：57600秒不变，从首次真实模型计算起计，包含等待、失败、CPU账户等墙钟时间。
- `first_model_at=1794901484.3200452`和既有累计GPU814.536823秒均不重置；失败计算继续计费。14小时是累计硬上限，不是从修订时重新给予14小时。
- 模型结构、两臂、初始化、数据、窗口、验证2048、训练3000updates、batch64、优化器、损失、选点规则、种子、两流20路径、交易规则、经济评价和bootstrap全部不变。
- 16:25—16:45资源守卫、watchdog、工作锁与root门禁保持。墙钟预算仍需按实际已用时间核验，不能只凭GPU估算判定通过。
