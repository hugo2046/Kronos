# MC40延迟反馈适配方案与防泄漏规则

2026-11-04。阶段为方案与数据时点审查。首轮研究建议用成熟真实标签在线校准MC40两层适配残差的强度，检验能否改善随后发出的选股信号。收益尚未评估。执行地点为dev-debian，原G1为主基准，已采纳MC40为参照。本轮文档及索引更新完成后，下一阶段为工程和数据可用性门禁。

## 1. 单一假设与方法选择

假设是行情变化会让既有适配器在某些阶段作用过强或过弱，少量、延迟的真实反馈可能校准这种偏差。候选暂名 **MC40-TTA2（完整十日标签、滞后一交易日）**。

对最后两层分别使用 `h + a_l × Δ_l(h,z)`，两个标量a初始均为1。Δ为原MC40状态适配残差，z为各股票当时90日历史产生的状态。两个a跨股票共享，由历史成熟横截面的平均损失更新。主干、tokenizer与原107712个adapter参数保持冻结身份，新增可训练自由度为2。a=1时必须复现原MC40。

方案比较如下。选择两标量方案是本次研究判断，数值默认值尚待工程门禁验证。

| 方案 | 可回答的问题 | 首轮选择 |
|---|---|---|
| 两层残差各一个标量 | 真实延迟反馈能否校准现有适配强度 | 推荐，限制容量便于追踪变化来源 |
| 更新整个107712参数adapter | 更大在线容量能否适应市场 | 容量与遗忘因素更多，留作后续独立议题 |
| 对最终分数做共享正斜率仿射校准 | 预测数值尺度能否校准 | 横截面排序可能完全不变，与Top50目标不匹配 |

TAFAS研究部分已观测标签和门控校准，发表于AAAI 2025。PETSA研究低秩校准，是ICML 2025 PUT Workshop工作。首轮借鉴其小参数、延迟反馈机制。两标量残差校准是本项目迁移假设，论文尚未验证A股选股收益。来源为[TAFAS原文](https://arxiv.org/abs/2501.04970)、[PETSA原文](https://arxiv.org/abs/2506.23424)，此前的官方代码核查见[专项笔记](MC40测试期适配论文核查_20261102.md)。

## 2. 建议锁定的首轮配置

| 项目 | 设计值 |
|---|---|
| 起始adapter | 已采纳MC40，训练seed100，原3000步权重 |
| 原MC40文件SHA | `d208a8b9f5359aa81bd6cfff473bf9aae193f0b37542e92b7ae39d00c649c402` |
| 状态参数 | a10、a11，直接标量，初值1，投影至[0.75,1.25] |
| 优化器 | SGD，lr=0.01，无momentum、无weight decay |
| 损失 | 原双头未来10-token平均CE + 0.01×mean((a−1)^2) |
| 每日更新 | 对当日唯一到期起点的有效股票计算完整横截面平均梯度，再更新一次 |
| 微批 | 股票代码固定排序，batch64，尾批按样本数加权，累计后统一clip全局梯度范数1 |
| 样本次数 | 每个起点/股票窗口最多使用一次，以样本ID持久化去重 |

| 随机流 | 更新流固定seed100并保存状态，推理按日期重置42/100，两类流隔离 |
| 候选选择 | 一个固定配置，使用每日真实在线状态，发行信号后追加归档 |
| 故障处理 | 非有限梯度/损失、原始数据或身份不符时终止该运行并记录，先修工程后原状态恢复 |

数值是保守的研究设计值，当前没有证据表明最优。首轮验证目标是稳定、可审计的延迟反馈。出现全程无参数变化、长期贴边或CE与排名无改善时如实报告。所有学习率/边界/频率修改都形成新协议，W3/W4结果不得用于回填本轮参数。

远端原训练 `state_adapter/train.py:110–123` 在完整已成熟的90+10窗口上构造shifted token输入，调用 `use_teacher_forcing=False`，该开关控制粗细token前向。首轮复用这个确切损失语义，保留目标位置89..98。先前论文笔记中泛称“teacher forcing”不足以指定实现，应以这里的源码语义为准。梯度经冻结网络回传到两个a，训练时关闭dropout。生成的离散价格路径只用于信号和评价。

## 3. 模拟时钟和成熟规则

使用交易所交易日序列d0,d1,…，分别记录行情发生时间、数据发布/入库可用时间available_at、决策发行时间issue_at、成交时间execute_at。时区固定Asia/Shanghai。设计值为每日18:00冻结数据快照、18:15发行信号。更新侧 `label_cutoff(t)=d(t−1) 18:00`，推理侧 `input_cutoff(t)=dt 18:00`，两个截止都早于本日18:15发行。18:00之后到达的数据不进入该日快照。A阶段先核查历史版本能否支持这个发布时间假设，条件不符则门禁失败，不能静默移动截止。

- 起点u在交易日du的收盘数据可用后发行预测。输入使用截至du的90个有效历史观测，目标日历为du+1至du+10。目标股票池和历史输入在u时固化。
- t日发行前，更新侧最多使用上一交易日d(t−1)已经收齐并实际可用的数据。推理侧最多使用dt收盘且在issue_at之前实际可用的数据。
- 当前唯一到期起点为u=t−11，即十日目标止于d(t−1)。十个目标日所有必需字段、复权依赖和标签编码依赖均可用，样本才可训练。
- 该到期起点中缺失、停牌或字段未按时到达的样本逐条记录并跳过。首轮不回补晚到的样本。当天没有完整有效样本则a保持上次值。
- 所有数据可用并完成一次更新之后，固定本日模型版本，生成当日信号。t+1日开盘后，交易引擎才处理这个信号。

具体例子中，d0发出对d1…d10的预测。d10收盘后完整标签刚成熟，d10的信号已经按旧参数发行。d11发行前才用这组标签更新，随后发行d11信号，用于d12开盘决策。

必须采用交易日序号，不能按10个日历日加减。每日issue_at固定为18:15，数据完成状态必须满足18:00的快照截止，不能只用date日期代替真实可用时点。

## 4. W3/W4的状态隔离

两窗口各自从原MC40、a=(1,1)、空队列、空已消费集合、初始更新RNG开始。W3从2025-07-01开始，W4从2026-01-05开始。输入的90日历史允许来自窗口开始之前，但首轮在线监督样本只来自该窗口已经发行的起点。

每个窗口最初11个发行日保持a=1，最早在第12个发行日更新。日历索引以窗口首日为d0，d0…d10均冻结，d11首次消费d0样本。W4不继承W3的参数、队列或梯度状态。既定窗口之间的暖启动不是本轮协议。若末日为dE，最后允许消费的起点为d(E−11)。最后11个起点d(E−10)…dE的反馈均不在本窗消费，包括标签恰在dE成熟、需等d(E+1)才可更新的d(E−10)。完整历史信号仍然发行，窗口终点之后的反馈丢弃。

封存边界为2026-07-24。预测目标的未来日历可以延伸，模型和适配器不得为这些日期获取真实行情或标签。

## 5. 数据读取边界及历史版本

### 5.1 先限制读取，再构造样本

现有远端 `kronos_qlib/windows.py:92–101` 的fetch_end是未来第10个目标交易日，随后在132–134行将输入截到起点。现有 `state_adapter/market_guard.py` 仅约束全局2026-07-24封存线。这个组合需要增加逐发行时点的限制才能用于TTA。

新的在线数据接口必须在调用底层之前检查边界，并对实际返回数据再检查一次。

| 消费者 | 允许的最大真实行情时点 | 其他要求 |
|---|---|---|
| t日预测输入 | dt且available_at≤dt 18:00 | 原始价格、成交量、状态和池资格在同一时点下可见 |
| t日适配更新 | d(t−1)且available_at≤d(t−1) 18:00 | 还须属于已发行起点u=t−11的完整目标集合 |
| 目标日历 | 已发布的交易所日历 | 仅日期及时间特征，独立接口 |
| 执行/评价 | 截至2026-07-24的必要行情 | 独立进程和输出目录，不能把收益或未来价格送回模型worker |

学习侧只允许指定的原始字段，拒绝能够在底层引用后续行的表达式，例如负向Ref、前瞻均值、居中滚动统计。数据库服务端计算的归一化、排序、复权转换也必须满足相同as-of规则。所有缓存key包含as_of、数据版本、字段、股票集合、起点和协议SHA。整段W3/W4预读缓存不能直接传给在线worker。

### 5.2 available_at和复权是运行前门禁

现有只读检查没有证明DDB保存了每个历史字段的发布版本。事件日期早于t，不足以证明现在数据库中的最终修订值在当时可用。执行前须核查以下条件。

1. 六项OHLCVA、停牌字段、历史池成员及必要复权因子可追溯其available_at或历史版本。元数据缺失时标为缺失，不能补造发布时间。
2. 发行时保存原始90日输入、过去状态、归一化统计和哈希。反馈更新不得重取一个被后续修订过的“历史输入”。
3. 目标标签应使用成熟时已知的价格和公司行动，在发行起点的价格坐标中对齐。需要验证分红、拆并股、复权基准日改变时的例子，避免把未来调整因子写回过去的输入或标签尺度。
4. 原始分钟级入库时间若不可得，“次交易日可用”只能登记为历史模拟假设，不能据此宣称通过严格PIT发布版本审计。首轮工程门禁先查清差距，再决定数据是否足以执行该协议。

只读准备阶段继续使用已批准数据源。若没有可用历史版本，方案状态标为“数据可用性门禁未通过”，先报告具体缺口，不启动自称无泄漏的正式经济评估。

### 5.3 历史归一化和标签构造

原 `state_adapter/data.py:89–93` 只用输入90行统计均值、标准差，再转换90+10行。在线反馈保留起点u当时的90行输入和历史统计，标签成熟后只附加10行目标。统计量不会用100行或全窗口重新估计。波动状态同样固定为u时历史。

tokenizer对100行窗口的编码只在全部目标已成熟后执行。即使编码器在窗口内混合信息，当前更新也只能依赖截至d(t−1)的可用值。必须单独核验时间轴和padding，排除100行之外的依赖。预测时的token编码只使用截至dt的90行输入。

## 6. 样本、交易与恢复审计

发行账本记录origin_date、issue_at、execute_at、股票、90行输入/状态/统计SHA、未来目标日历、模型底座/adapter/a版本、两条推理RNG身份、信号SHA。原始信号按日期追加写入，后续训练成功也不重新生成或覆盖过去信号。

更新账本记录adaptation_time、label_as_of、origin_date、样本ID、目标十日范围、最大实际available_at、输入和标签哈希、跳过原因、更新前后a、损失、梯度范数与clip、学习率、更新RNG、消费集合摘要。交易收益只进入独立评价账本。

所有同一起点股票共享固定价格尺度规则，更新按有效样本数平均，微批大小变化不能改变样本权重。横截面完整集合由起点资格和成熟时实际数据决定，不能用目标收益、未来池成员或未来存续情况筛选。

一次发行事务先保存可恢复的模型/队列/已消费集合/RNG和当前信号临时文件，再以事务ID提交。恢复时验证文件哈希和已提交序号，防止同一成熟样本被重复更新、漏掉更新、或者用新参数重写旧信号。只允许一个活worker。

## 7. 必须通过的因果与等价检查

| 检查 | 必须满足的结果 |
|---|---|
| 零更新、a=1 | 原MC40身份不变。W3/W4每窗首/中/末共6日×2流预测与冻结参考逐值一致，再确认完整日期/股票有限格 |
| 截断历史重放 | 完整数据顺序回放与截止t的截断数据回放，t及之前a、已发信号、队列可见部分完全一致 |
| 未来数据置换 | 仅在内存合成测试副本中改动t以后价格/标签/停牌/成员，t及之前所有状态和发行结果不变 |
| 可用时间置换 | 将一个标签available_at推迟，更新必须相应跳过，即使event_date已经早于t |
| 标签成熟边界 | 非交易日、缺第10日、窗口最后11个起点（包括第11个边界）、缺字段/停牌均按规则处理，没有未成熟标签入梯度 |
| 输入及价格尺度 | 改动u后数据不改变已冻结u输入/90日统计/状态，分红拆股例子坐标一致 |
| 梯度隔离 | 只有两个a有梯度，底座/tokenizer/107712个adapter参数哈希始终一致 |
| 随机流隔离 | 增加一条只读诊断不会改变当日推理结果，恢复前后更新流和推理流一致 |
| 窗口隔离 | W4结果与单独启动W4一致，W3状态无法影响W4 |
| 历史不可变与断点恢复 | 训练前后旧发行SHA一致，中断恢复与不中断回放的a/样本消费/信号逐值一致 |
| 输出可交易时点 | t日发出的信号最早进入t+1开盘交易，订单和交易回执不向在线更新泄漏 |
| 封存及隐藏读 | 请求在读前就被as-of拒绝或限制，返回字段再核验。全局截止仍为2026-07-24 |

以上未来置换只使用合成数据或已获准开发窗口的内存副本，绝不读取封存数据来做测试。每日输入截止的改造还必须证明基准a=1的有效股票格未改变；若不一致，先解释执行语义差异，再谈收益对照。

## 8. 执行阶段与交付

A阶段在dev-debian进行源数据可用性/复权语义检查、合成时钟测试、a=1等价和梯度恢复检查，生成独立审查记录。当前任务完成方案和索引，A阶段尚未执行。工程改动与数据规则通过后，锁定协议、候选配置和source SHA。

B阶段按两独立窗口严格顺序模拟，同一个在线参数状态用于当日42和100两条推理流。更新只发生一次，不能给两流各自训练一套a。初期冷启动a=1的日期可在已验证身份下复用冻结MC40信号，其余按相同预测出口生成。总计520日期×流，监控实际额外计算，GPU预算建议6小时、墙钟8小时，从正式协议启动起累计，包含真实a=1复现及后续候选计算，恢复不重置。任一硬上限触发时保存已完成事务并停止计算，标记“预算耗尽、未完成”。部分窗口仅可披露进度，不参与本轮通过判定。扩大预算需要另行登记和授权，不能重置账本。正式候选完成后按统一规则回测。

最终报告至少包含原G1、冻结MC40和MC40-TTA2的扣费累计图、复利、夏普、MDD、费用、换手、相对两基准的配对20日循环块区间（5000次，seed100），另列两个a的逐日曲线、成熟/跳过样本数量、实际更新次数与耗时、每时点最大读取日期和历史版本审计。指标收益与风险分列。固定两窗都超过原G1/MC40的净累计收益才通过收益门槛，两窗夏普不低于MC40且MDD幅度不更大才通过风险门槛。

点估计门槛与不确定性分别报告。任一主要相对收益差区间跨零时，只能称“开发窗口点估计改善、增量证据不足”。即使点估计门槛通过，也不自动采纳或宣称稳定经济增量。收益差区间不能替代夏普、MDD各自的统计检验。

冻结MC40评估工程的a=1对照必须通过。任何历史领先只提供开发期证据，反复查看窗口与单seed限制在报告中披露。未来若出现可重复增量，再设计独立确认或固定离线两标量控制，以区分在线反馈和额外自由度。
