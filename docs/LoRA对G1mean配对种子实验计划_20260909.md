# LoRA 对 G1 mean：固定 Qlib 口径与配对种子实验计划

> 用户选定的主原则：**固定当前Qlib回测口径，判断新方案是否超过G1 mean；用配对种子确认提升是否重复出现。** 执行者Debian zcode使用using-superpowers / executing-plans，按checkbox推进。本轮是新的生成式主干LoRA实验，不是TimesFM复现，不重开MH1/G10 DualHead-only或DHead蒸馏。

**目标：** 在项目现有G1模型上，只训练注意力LoRA，检验扣费后mean曲线是否高于原G1 mean，并区分适配收益与推理随机采样差异。

**架构：** 从同一个G1 s100 tokenizer/predictor开始，冻结原权重，对predictor自注意力q/k/v/out线性投影注入零初始增量LoRA，沿用生成token CE；Qlib R管理每次独立训练/推理/回测，唯一epoch文件与明确身份关联，避免复用未核验历史cache。

**技术栈：** Python3.10+、PyTorch、Qlib/R、pandas/numpy、matplotlib、pytest、loguru；Path、类型注解、Sphinx docstring和中文关键注释。

## 2. 两种基线，名称与用途不可混淆

| 名称 | 定义 | 用途 |
|---|---|---|
| `G1_original_mean` | 原`0b982e8`绑定的G1 s100 FULL信号文件，两窗固定 | 用户主比较对象，所有seed都与它比 |
| `G1_paired_s` | 同一G1 s100权重不更新，以推理seed=s重新生成mean | 排除随机采样差异的配对对照，不能替换主基线 |
| `LoRA_s` | 同一G1 s100权重上训练seed=s的LoRA，推理也用seed=s | 优化候选 |

种子预定为100/101/102。G1_paired没有重新训练，三份输出只代表三个推理随机种子；LoRA三份包含adapter初始化/训练与推理种子变化。报告不能把它说成三组独立G1训练实验。

## 3. 固定LoRA与训练设计

| 项目 | 固定配置 |
|---|---|
| 起点 | G1 s100 predictor + G1 tokenizer，原权重全部冻结 |
| 目标层 | `predictor.transformer.<i>.self_attn.{q_proj,k_proj,v_proj,out_proj}`，实际层数从G1配置读取并冻结，预期12层 |
| LoRA | rank8、alpha8、额外dropout0；增量 `(alpha/r)*B(A(x))`，A用固定seed初始化，B全零；原Linear weight/bias均冻结 |
| 可训练量 | 若12层、维数832，48个投影共638,976个LoRA参数；按公式与实际allowlist核对，不冻结成错误硬编码 |
| 禁止更新 | tokenizer、原attention weight/bias、DualHead、dep_layer、embedding、norm、FFN与时间编码 |
| 训练语料 | G1同源`finetune_suite/data/ashares/`，训练2014..2024；验证2025H1，所有样本窗口端点留各自段内 |
| 目标 | 原粗/细next-token CE均值，token输入[:-1]、标签[1:]、use_teacher_forcing=False；不蒸馏、不增加收益标签loss |
| 超参 | batch50、2000更新/epoch、15epochs；AdamW lr=4e-5、betas=(0.9,0.95)、wd0.1；OneCycleLR pct_start0.03/div_factor10，其余默认值显式序列化；clip_grad_norm=3.0；FP32 |
| 选点 | 固定验证400批，最低CE的epoch，并列最早；只用这一个状态推理回测，不跑多个epoch挑交易收益 |
| RNG | 训练继续原随机流，训练epoch完成后用validation_rng隔离验证seed100，finally恢复Python/numpy/CPU/已使用CUDA状态；三seed使用相同验证样本与验证随机规则 |

本轮是“G1继续做低秩适配”，不同于G10A1从官方predictor起步。训练过程仅允许新LoRA参数变化；LoRA额外dropout为0，基础predictor保留正常train模式，tokenizer恒eval/no_grad。

- [ ] 注入后adapter零增量模型在eval固定输入上的logits与原G1一致（CPU合成精确，真实小样本采用预声明浮点容差），关闭adapter后恢复原G1输出。此门禁先于任何正式训练。
- [ ] 一次合成更新后，变化张量只能属于LoRA A/B；原基底与tokenizer完整state哈希不变。保存加载adapter后再次对拍。
- [ ] 原G1训练归一化、窗口采样、样本顺序等实际实现作为协议的一部分记录，检查标签不跨train/val时间边界；不顺手改变预处理。样本键/LR摘要与每epochCE写R。
- [ ] G1_paired和LoRA同一seed的推理都在加载结束后重新播种，日期、股票顺序、batch32、最后一批规则相同；不能因LoRA初始化多消耗随机数而改变起始推理流。

## 4. 工程范围从简：Qlib R + 通过真实入口的少量门禁

新增`lora_mean_pilot/`，建议`adapter.py`、`train.py`、`evaluate.py`、`run.py`；配置放一份冻结JSON/YAML。测试`tests/test_lora_mean_pilot.py`。允许修`qlib_mean_comparison/run.py`的R接线与基准符号配置，但不得改旧结果或回测参数。

不要直接复用`c903a2d`尚未验收的完整G10训练/缓存路径。允许提取已验证的RNG纯函数，但须去掉`eval`并通过本轮生产入口测试；不要另建实验框架。

- [ ] `with R.start(experiment_name=...,recorder_name=...):`管理每次run；训练与推理分别record，参数记录adapter配置、权重/数据/代码SHA、seed和窗口，metric记录CE/运行耗时。图片与Parquet使用`R.save_objects(local_path=...,artifact_path=...)`或log_artifact，不把Path对象当图片序列化。
- [ ] 每epoch保存唯一文件`adapter_epoch_001.pt`等并记录SHA与CE；best只是一条指向确切epoch文件的索引。保存→载入→产生信号绑定实际adapter和基底SHA，不能仅依赖名称best。
- [ ] 本轮从简**不提供自动断点续训**；已存在run不可覆盖，失败保留原run并报告剩余预算，不自动重训。只做最多约一小时级的单adapter训练，避免未经测试的复杂恢复路径继续干扰研究。
- [ ] 推理文件绑定run/基底/adapter/seed/输入/窗口/配置/输出SHA；不得因旧同名文件存在而复用。现有legacy信号只作为明确标记的主基线，不签成新生成链。
- [ ] 当前Qlib接口需修正`R.start`未进入with、Path被保存成对象两个问题；先用合成R run验证参数/真实文件artifact/错误状态，再进行真实运行。
- [ ] GPU预算按attempt逐批/逐日期累计，与R记录对应；先计时再检查不能无限跑完一整窗才发现超预算。登记cron优先，批边界守卫、让位前不丢已保存输出；无法安全暂停的单训练run避开守卫窗口再启动。
- [ ] CPU合成集成测试通过完整“新run→两epoch→不同best/final→加载best→fake两窗信号→Qlib/R产物”路径；测试必须能抓到局部导入未绑定、缺checkpoint、错schema/错SHA等实际入口错误，不仅测辅助函数。

## 5. 固定推理、股票日集合与Qlib口径

W3=2025-07-01..2025-12-31，W4=2026-01-01..2026-07-24，逐日FULL；标签尾部不能裁交易信号。lookback90/H10/N20/T1.0/top_p0.9/top_k0/clip5/max_context512，mean=`mean(pred_close[t+1..t+10])/close_t - 1`。不试min/max/last或其他日期裁剪。

以原G1信号的有效股票日集合为固定候选集合，并核对t日PIT与90日历史输入资格；所有新臂必须在其上产出有限信号。新臂缺格视为运行失败，不能按新模型的缺失再缩池以改变基线。若发现原G1集合与当前数据资格不一致，preflight先解决来源/版本问题，不在看收益后删格。

Qlib TopkDropoutStrategy top50/drop5/hold5、SimulatorExecutor day、open成交、买0.001/卖0.0015/min_cost5、limit_threshold0.095、资金1亿，全部实际默认值从`0b982e8`使用的Qlib版本记录固定。指数经济身份为沪深300：该DDB构建可能使用`SH000300`而非`000300.SH`，选择能逐值复现旧report.bench的标识并冻结，不能因编码变化误换指数。

实测t日信号→t+1开盘，不额外平移；各臂新建strategy/executor/account。不得混用自定义v2结果与Qlib结果。

主曲线 `curve=(report['return']-report['cost']).cumsum()`；“高于G1 mean”指同窗末日曲线差>0，不要求每天都高、不要求跑赢沪深300。不另加IC/t值/绝对盈利作为成功前提。复利/回撤/成本/换手为附表，明确与cumsum区分。

## 6. 两阶段配对种子确认与停止条件

令每窗 `D_original(s,w)=curve_LoRA(s,w)[-1]-curve_G1_original(w)[-1]`，
`D_paired(s,w)=curve_LoRA(s,w)[-1]-curve_G1_paired(s,w)[-1]`。均报告百分点差和逐日差额曲线。

### 阶段1：seed100 pilot

- [ ] preflight先锁基线、数据/模型/适配配置、评价规则和预算；用同一验证期历史日做少量真实smoke，估计两臂两窗推理成本及条件确认阶段总成本。smoke不看测试收益，不计入正式模型。
- [ ] 训练LoRA100，只选验证CE最佳adapter；生成G1_paired100/LoRA100两窗mean。全部两臂两窗落盘并校验后统一回测，不边看收益边改参数。
- [ ] 仅当两窗的`D_original(100,w)>0` **且** `D_paired(100,w)>0`时进入阶段2。否则报告“未超过用户基线”或“超过旧信号但配对采样对照不支持适配增益”，封存本配置，不搜索。

### 阶段2：seed101/102（仅阶段1通过且预算可覆盖）

- [ ] 按完全相同配置分别训练LoRA101/102，生成对应冻结G1_paired101/102；不根据pilot调整任何超参/窗口/候选集合。
- [ ] 三seed各自独立选验证bestCE；全部结果并列，不挑最好seed，不把三seed合成策略收益，也不把相同G1训练底座说成三次独立训练。
- [ ] “重复改善”固定定义：三个seed中至少两个在**两窗**均同时满足D_original>0与D_paired>0，且两窗各自的三seed D_original中位数和D_paired中位数均>0。
- [ ] 若只pilot通过、确认失败，则结论“单种子改善未重复”；若预算不足或运行失败则“确认未完成”，不能当成功或模型失败。不得超12小时自行增加预算。
- [ ] 重复改善成立也只说明这些已观察窗口下相对G1的改善；后续独立前向确认另议，不自动替换G1或读forward。
