# 多期限预测头蒸馏实施方案（DHead v1）

> 给 zcode / agentic workers：使用 `using-superpowers`，按 `executing-plans` 逐任务实施；需要独立子任务时可使用 `subagent-driven-development`。用下方 checkbox 跟踪实际完成状态，每阶段记录命令、退出码和产物。用户已选择此方向，常规实现决策自行完成；本轮交付方案，模型实现由接手者完成。

**目标：** 在已微调 G1 底座上实现直接预测未来 10 个期限收益的小型预测头，通过生成式教师蒸馏及有限联合适配，验证能否减少推理成本并保留或改善截面信息。

**架构：** 历史 OHLCVA → 冻结 tokenizer → G1 Transformer 历史隐状态 → 10 个期限 query 的单层交叉注意力头 → `[B,10]` 收益预测。先训练纯蒸馏基线，再做监督/蒸馏对照；条件通过后，仅在学生最后两层注意力中加入 LoRA。教师始终独立冻结。

**技术栈：** Python 3.10+、PyTorch、NumPy、pandas、PyArrow、loguru、pytest；路径用 pathlib，公共方法用类型提示、Sphinx docstring，关键逻辑中文注释。

## 3. 数据与时间契约

### 3.1 定义与字段

- L=90、H=10；输入顺序固定 `open, high, low, close, volume, amount`。
- 每条样本键为 `(decision_date, code)`，历史输入只到 t；未来日历可以使用，未来价格只用于标签。
- 真实标签 `y[t,h] = close[t+h] / close[t] - 1`，h=1…10；保持原始小数收益单位，不对标签逐日 z-score，以保留期限均值的经济含义。
- 学生信号 `score = prediction.mean(dim=-1)`，对应未来 10 日平均价格相对现价的收益；不能用第 10 日收益冒充。
- z-score 统计量只从这条样本过去 90 日获得，std 使用总体标准差，epsilon=1e-5，clip=5；标签和教师目标都由真实 close_t 反归一化后计算。
- 训练真实标签的 10 日路径须完整且有限。纯蒸馏试点也使用相同样本清单，使各臂可比。
- 历史价格缺失、非有限值、非正价格、交易日缺口：整窗剔除并记录原因。只允许相邻交易日，不跨缺口拼接；不执行 dropna 后滑窗。
- 成交量/成交额缺失处理固定为该窗剔除；这是一项 v1 数据选择，不宣称复现论文缺失处理。推理时仅按历史可得性筛选，不能根据未来标签是否存在决定是否发信号。

### 3.2 时间窗口

| 用途 | 决策日与标签边界 | 证据等级 |
|---|---|---|
| 头训练 | 2014-01-02～2024-12-31 内，且 t+10 交易日不晚于 2024-12-31 | 开发训练 |
| 头验证与选择 | 2025H1，且全部真实标签落在 2025H1 | 开发验证；G1 曾用此段选 checkpoint |
| 历史诊断 | 2025H2，且全部标签落在 2025H2 | 未参与本轮头拟合，但已被过去研究看过 |
| 历史回放 | 2026-01-01～2026-07-24；有标签的指标只计算 t+10≤末日的样本 | 已知行情，探索性 |
| 封存 | 2026-07-25 起 | 本轮不加载价格、标签或绩效 |

验证区间允许从前一区间带入历史上下文；不得让训练标签越过训练末日。使用交易日历计算 purge，不能仅硬编码日历减 10 天。

G1 本身已训练至 2024 年并在 2025H1 选权重，因此本实验是**已有模型的事后压缩/适配研究**，不能声称在 2014 年逐日拥有该模型，也不能把 2025H1 视为整个系统独立验证。真正 walk-forward 研究需要每折独立训练和选择教师，本轮不承担该成本。

### 3.3 固定样本预算

- 训练使用全 A 当日 PIT 成分；验证/历史诊断使用当日 CSI300。各臂清单完全相同。此分布差异明确保留，不得据结果挑子池。
- 训练候选日期由通过日历和标签边界的日期形成；等间隔取最多 512 个日期（在排序序列上 `np.linspace(0,n-1,min(n,512),dtype=int)`）。
- 每日按 `(date,code)` 稳定哈希排序取 128 股；不足 128 但至少 32 股则保留全部；少于 32 股则剔除该日并披露。最多 65,536 条训练样本，**不是全量 1,029 万行训练**。
- 验证取最多 32 个等间隔日期，每日同法取最多 128 股；历史诊断取最多 64 个等间隔日期、每日至多 128 股。
- 清单 seed=20260905；训练 seed=42，条件确认种子 43/44。使用 SHA256 稳定哈希，不用 Python 内置 hash。
- DataLoader 按已冻结清单索引读取，不在 `__getitem__` 内随机另选样本。按日形成 batch，IC 必须在同日计算；shuffle 仅改变日顺序。
- 这是有预算上限的先导方案；若失败，仅关闭此规格，不证明“读出架构或广度已被穷尽”。

## 4. 学生结构与核心公式

### 4.1 多期限头

输入为 G1 最后 RMSNorm 后全部历史隐状态 `[B,90,832]`。

1. `Linear(832,128)` 投影；
2. 10 个期限 embedding 作为 query，结合未来日历 5 项 embedding 的和（minute/hour/weekday/day/month，各为128维），确保假期位置可表达；
3. 单层 `MultiheadAttention(128,4,batch_first=True,dropout=0)`，K/V 来自历史投影；
4. query 残差加 LayerNorm，最后共享 `Linear(128,1)` 输出 10 个收益。

期限 query 只看截至 t 的历史，彼此不使用真实未来标签。第一版不增加 query 间 self-attention 或额外 MLP。

`head.py` 核心计算参考（构造器需按上述定义，公共方法补齐 Sphinx 文档）：

```python
def forward(self, hidden: torch.Tensor, future_stamp: torch.Tensor) -> torch.Tensor:
    memory = self.proj(hidden)
    calendar = sum(
        embedding(future_stamp[..., j].long())
        for j, embedding in enumerate(self.calendar_embeddings)
    )
    query = self.horizon_embedding.weight.unsqueeze(0) + calendar
    pooled, _ = self.attn(query, memory, memory, need_weights=False)
    return self.out(self.norm(query + pooled)).squeeze(-1)
```

calendar embedding cardinalities 固定 `[60,24,7,32,13]`；horizon embedding 为 `[10,128]`。构造时校验 G1 d_model=832，并记录实测可训练参数数目，不依赖估计文字。

### 4.2 教师目标

- 教师固定 G1 s100 tokenizer+predictor，全部 eval，权重 SHA256 入 manifest。
- 每个样本生成 3 组独立 N=20 平均 close 曲线。组 0 为蒸馏 target，组 1/2 仅用于估计教师自身波动和独立保真评估，禁止拿它们挑学生 checkpoint。
- 教师收益 `y_teacher[h] = mean_N(pred_close[h])/close_t - 1`。保留 `[sample,replica,10]` 的组均值；仅在试点诊断时保留单路径。
- 每次以 **一只股票、固定 N=20** 调用原 `predict`，由 SHA256(`protocol_hash|date|code|replica`) 前 8 字节映射为 seed；用 `torch.random.fork_rng` 限定 CPU/所用 CUDA 状态。实现顺序、恢复、外层批次改变后，同设备相同样本应一致。
- 该keyed RNG协议与既有“每日重置seed42后批量推理”的路径样本不同。T臂须按新协议重算为本轮教师基准；旧G1收益仅作历史引用，不要求本轮T逐位复现旧数字，也不能把随机协议变化的差值归给预测头。
- 本轮不声称实现了路径级 N 嵌套不变性。固定单样本调用代价要在试点实测；不为赶预算偷偷换批量采样协议。
- 教师生成与标签构建分离：传给教师的 provider 只暴露 ≤t 行情，未来 timestamp 由日历提供；用 future perturbation 测试确认教师输入不变。

### 4.3 损失

从训练标签计算各期限尺度 `scale[h]=max(std_train(y[:,h]),0.01)`，保存并冻结。以下所有均方损失先除以同一个 scale，避免直接把数量级极小的收益 MSE 与 IC 相加。

```python
def normalized_mse(pred: torch.Tensor, target: torch.Tensor,
                   scale: torch.Tensor) -> torch.Tensor:
    return ((pred - target) / scale).square().mean()

def daily_ic_loss(pred: torch.Tensor, target: torch.Tensor) -> torch.Tensor:
    # 调用者保证一个 batch 是同一日、至少32只股票；target是10日期限均值。
    p = pred.mean(dim=-1)
    y = target.mean(dim=-1)
    p = p - p.mean()
    y = y - y.mean()
    denom = (p.square().sum() * y.square().sum()).sqrt().clamp_min(1e-8)
    return 1.0 - (p * y).sum() / denom
```

- 蒸馏损失 D=`normalized_mse(pred,y_teacher_replica0,scale)`。
- 真实监督 S=`normalized_mse(pred,y_real,scale)`。
- 排序损失 I=`daily_ic_loss(pred,y_real)`；标签方差为0的日跳过 IC、计数并保留 MSE。预测方差为0时使用上述 epsilon 保持有限。
- v1 任务损失固定 `0.5*S + 0.5*D + 0.05*I`，不是最优参数的宣称；本轮不搜索系数。

## 5. 实验臂、训练和选择

| 臂 | 初始化 | 可训练部分 | 损失 / 用途 |
|---|---|---|---|
| T | 已冻结 G1 | 无 | 原 AR 教师，3 组重复 |
| D0 | 同 seed 小头初始化 | 仅头 | D，纯压缩基线 |
| S | 与D0相同头初始化 | 仅头 | S+0.05I，直接监督对照 |
| D1 | D0 的 best-D checkpoint | 仅头 | 0.5S+0.5D+0.05I，蒸馏后适配 |
| D2（条件） | D1 的 best-task checkpoint | 头+最后2层q/v LoRA | 同D1损失，受限联合适配 |

所有头 AdamW lr=3e-4、wd=0.01、gradient clip=1、FP32 损失；每阶段最多15 epoch，patience=3。D0 按验证 D 最小选；S/D1/D2 按验证 `S+0.05I` 最小选，tie 取更早 epoch。记录全部 epoch 指标及 checkpoint，不依据诊断/回放收益选 epoch。

所有梯度步按日batch等权，所有验证loss先按日计算再对日平均；各期限等权。teacher重复波动仅用于保真评价，不能作为真实收益风险预测输出。

D0/S 使用同一清单，每 epoch 每日batch恰访问一次。D1 有额外预训练，D2 有额外适配，因此不能把 D1−S 或 D2−D1 全归因于一种机制：

- 增加 `S-long`：S 的同一训练轨迹延长至 D0实际epoch+D1实际epoch 总次数，损失不变，独立按相同验证指标选点；报告与D1的等优化步数对照。
- D2 运行时增加 `D1-cont`：从同一个D1起点继续训头，步数与D2相同；D2−D1-cont 才用于判断解冻增量。
- S-long与D1-cont为预算匹配对照，不受单阶段15 epoch上限或独立早停提前截断；运行到配对臂的实际步数，保留过程checkpoint，再按相同验证指标选点。匹配继续训练时的batch顺序。
- 明确这些对照匹配优化步数，不匹配GPU耗时；同时报告两者。

LoRA：仅末两层 attention 的 q_proj、v_proj，rank=8、alpha=8、dropout=0，A Kaiming初始化、B零初始化。学生其他层 eval 且冻结；LoRA参数与头 requires_grad=True，LoRA lr=1e-5。教师和学生必须是不同实例，不能共享可变模块。

**关键实现：** 现有 `KronosFrozenBackbone.extract` 有 `@torch.no_grad`，构造器还冻结全部参数。包内实现学生 extract：tokenizer 与前10层可在 no_grad 下计算，最后2层在启用梯度的环境运行；不要把整段包进 no_grad。末两层保持 eval 不妨碍梯度，能避免随机 dropout 成为额外变量。LoRA全零时学生隐藏输出与原G1对拍，再验证反传只更新指定权重。

缓存：冻结阶段可按日保存 BF16 隐状态，但先对比 FP32 reference，固定试点样本上收益预测最大绝对差≤1e-4才启用，否则用FP32。D2禁止复用最终隐状态缓存；可缓存tokenizer tokens或末两层之前的冻结激活。manifest 写明缓存dtype及截断位置。

### 8.2 保真与速度门禁

定义teacher-repeat误差 R=`MSE_norm(replica1,replica2)`，学生独立误差 E=`MSE_norm(student,replica1)`，均在同一验证样本清单按日等权平均。用于比值时分母加1e-8。

pilot的D0达到 E/(R+1e-8)≤2.0 且每日student/replica1信号Spearman均值≥0.8，才扩大main。有效相关日期不足80%视为不足，不记通过。这是工程容差，不是统计显著性。

main压缩门禁：在第3节历史诊断清单，重复上述两条件，并且学生端到端中位耗时≤教师单次N20耗时的50%。计时同硬件、同有效样本、含预处理/tokenizer/主干/头、不含取数和磁盘IO；各预热5次、测20次、CUDA同步，报告p50/p95和峰值显存。学生可用合理批量；教师记录固定单样本协议及原批量G1两种性能，速度收益需相对原批量G1也成立。

保真未过：保留S直接监督结果，D1/D2不自动扩大；原因标成“本规格蒸馏保真不足”，不把teacher-repeat波动当成市场不确定性校准。

### 8.3 D2继续条件

main D0验证保真通过，且D1在验证 `S+0.05I` 优于D0，同时D1的E/R≤2.0，才运行D2及D1-cont。是否触发由验证数据决定，不能因2025H2或2026历史收益好看临时解锁。

### 8.4 回测门禁与研究结论
