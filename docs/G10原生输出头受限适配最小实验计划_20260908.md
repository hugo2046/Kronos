# G10 原生输出头受限适配：最小实验与新基准预注册

> Debian 执行者使用 using-superpowers / executing-plans，按 checkbox 执行。用户在 G1 日期对照验收后要求继续推进；本计划承接“完整逐日基准＋真实 v2＋一个受限适配方案”的最小实验，不启动原五臂方案。

**目标：** 在相同生成式训练目标、起始权重和数据下，检验只训练 Kronos 原生 DualHead，能否较全参数微调保留更稳定的跨窗口预测信息，并记录这种信息是否转化为扣费超额。

**架构：** G1 tokenizer 固定；两臂从同一官方 Kronos-base predictor 出发，A0 更新全部 predictor 参数，A1 仅更新已有 DualHead 两个输出投影。仍生成未来 OHLCVA token 路径，用固定 mean 信号评价；不新增收益回归头、不蒸馏、不改变 tokenizer 或词表。

**技术栈：** Python 3.10+、PyTorch、pandas/numpy、loguru、pytest。Path、完整类型注解、公共 Sphinx docstring、关键中文注释。

## 1. 身份、范围与已知证据

- 分支 `codex/g10-head-pilot`，origin=`git@github.com:hugo2046/Kronos.git`；基线 `f3e9807`，Mac worktree `/private/tmp/kronos-g10-head-pilot`。
- 本轮新增编号 **G10H-pilot**，不是改写 `55e76b7` 路线图原判据。原 +14.33% AER 锚、±26pp 和原 Q0~Q4 在本轮均不使用。
- 已知：MH1 无稳定增益且训练池不符合原 PIT 协议；DHead 蒸馏 pilot 保真门禁失败、main/D2 锁定；G10 原 A0~A4 只发现计划。原生 DualHead 的生成 token 似然适配尚无已执行证据。
- 选择 A1 的理由：沿用已有输出投影、无需新结构，参数范围易严格核验；直接检验“只调整隐状态到 token 概率的映射是否足够”。没有假定它一定比 LoRA 或全参数更好。
- 本轮只做两臂×一个训练种子×两个选定状态；不启动 A2/A3/A4、不搜索 lr/词表/秩/训练池/期限/采样数、不追加收益头；不解锁 DHead。
- 现有历史均为已观察数据；本轮是机制探索，不称首次样本外、不能更改现有策略或自动注册 forward。
- 不读取 2026-07-25 起真实行情/收益/特征/登记信号。完整逐日推理需要未来时间戳时，**只允许交易日历日期**用于模型输入，不访问这些未来日期的任何观测值；未来模型预测也不得当标签。

## 3. 训练协议：相同起点、相同样本与更新预算

| 项目 | 固定值 |
|---|---|
| tokenizer | 原 G1 微调 tokenizer；eval、no_grad、全参数冻结，按文件SHA256绑定 |
| predictor起点 | 官方 Kronos-base，与既有G1训练起点一致；两臂完整初始state_dict哈希相等，不使用G1已微调predictor作为训练起点 |
| A0 | 更新全部 predictor 参数；仅用于本次同协议对照，不能拿历史G1代替这次训练 |
| A1 | 仅 `head.proj_s1.{weight,bias}` 与 `head.proj_s2.{weight,bias}` 更新；embedding、dep_layer、transformer、norm、时间编码全部冻结 |
| 训练语料 | G1同源 `finetune_suite/data/ashares/`，2014..2024历史全A语料；显式声明为原有全A历史集合，不冒充逐日csi300 PIT |
| 验证 | 原G1同源2025H1，窗口全部留在2025-06-30以前；只用于CE选点，不读W3/W4选模型 |
| 目标 | 原 `DualHead.compute_loss`，粗/细token CE等权均值；输入token[:-1]、目标token[1:]；原trainer的 `use_teacher_forcing=False` 保持不变，细头条件来自粗头detach概率采样，不能改喂真实s1标签 |
| 预算 | seed=100，batch50，2000更新/epoch，15epochs固定完整跑；每epoch验证400批，采样集合固定 |
| 优化器 | AdamW，betas=(0.9,0.95)、wd=0.1；OneCycleLR max_lr=4e-5、pct_start=0.03、div_factor=10，其余原trainer默认值显式写入新协议 |
| 精度 | 原trainer FP32，无autocast/GradScaler，梯度裁剪max_norm=3.0；两臂一致。CUDA/TF32设置在preflight记录冻结，不单臂启用新AMP/量化/内核 |
| 选点 | 验证CE最低epoch（严格小于更新，并列最早）；另固定epoch15；CE无有限值则实验无效，不用测试收益选点 |

只限制梯度更新，不把整个 A1 predictor 强制 eval 造成额外 dropout 差异；两臂 predictor.train() 使用相同原训练随机层，tokenizer始终eval。推理时两臂全部eval。两臂粗头概率随训练不同，抽出的s1 token允许不同，这是训练机制的一部分；要求一致的是采样方法和种子规则，不能强制相同token改变模型分布。验证CE除固定400批样本外，每轮进入验证前保存训练RNG、重置验证RNG为100、结束后恢复训练RNG；这是本轮显式的配对选点约定，两臂同用，避免验证采样扰动下一轮训练随机流。

已核实接口：`model/kronos.py:Kronos.head` 是 `model/module.py:DualHead`，内部为 `proj_s1`、`proj_s2`；预计约170万可训练参数，实际数量与精确参数名列表写入协议。禁止因名字相似解锁 tokenizer.head。

参数限制运算应等价于：

```python
allowed = {
    "head.proj_s1.weight", "head.proj_s1.bias",
    "head.proj_s2.weight", "head.proj_s2.bias",
}
names = {name for name, _ in predictor.named_parameters()}
assert allowed <= names
for name, parameter in predictor.named_parameters():
    parameter.requires_grad_(arm == "A0" or name in allowed)
trainable = [p for p in predictor.parameters() if p.requires_grad]
```

## 4. 最小执行范围与资源门禁

本轮仅训练 A0_s100、A1_s100。正式评价状态为 A0_bestCE、A0_e15、A1_bestCE、A1_e15；bestCE=e15时同一个权重只推理一次并记录别名，不能当成两个独立样本。

推理固定：lookback90、H10、sample_count20、T1.0、top_p0.9、top_k0、clip5、max_context512，输出mean信号。公式为 `mean(pred_close[t+1..t+10]) / close_t - 1`，其中pred_close来自KronosPredictor对20条采样路径的既有聚合输出；与 `baseline_suite.signal.compute_variants_from_preds` 的mean分支对拍，正式训练前记录函数来源和表达式。不能临时改为终点收益或另一种路径汇总，只评价一种变体，不跑min/max/last筛选。

推理随机seed固定100；相同评价日期/股票顺序/批大小，重置随机流规则对所有checkpoint相同；记录实际batch和最后一批处理方式。单一训练/推理种子是pilot限制，不声称跨种子稳健。

## 5. 评价与新的探索性判据（事先冻结）

**主问题是“训练末期是否保留预测信息”，不是复现旧AER锚。** 只比较本次A0/A1，同一日期、同一股票、同一标签计算日RankIC；多状态共同有效股票日和原始有效天数均报告。标签缺失日不填零；窗口内日历距离计算NW，跨窗按已核验的分段HAC，不拼接成相邻交易日。

令 `IC(a,s,w)` 为臂a、状态s、窗口w的日RankIC均值；`drop(a,w)=IC(a,bestCE,w)-IC(a,e15,w)`（可以为负，负代表训练末期更好）。

| 门禁/判据 | 本轮固定定义 | 含义 |
|---|---|---|
| V有效性 | 原始资产身份/样本配对/冻结参数范围/预算/完整逐日信号/真实v2接线全部验证通过 | 不满足则实验无效，不能判模型失败 |
| I信息保留 | A1的bestCE和e15在W3/W4的k10均值均>0，且两窗各自 `drop(A1,w)≤0.01` | 0.01为事先选定的绝对IC容忍带，不是统计显著性阈值 |
| P相对末期 | A1_e15−A0_e15 的日IC差两窗均值均>0，分段合并NW t>2 | 探索性相对信息增益，不是多重检验修正后的显著声明 |
| S稳定性改善 | 两窗各自 `drop(A1,w)≤drop(A0,w)`，且至少一窗严格小于 | 若A0根本没有末期劣化，不得宣称验证“挽救崩塌” |
| E经济可用性筛选 | A1_bestCE和A1_e15均在两窗完整逐日指数净超额累计>0 | 只用固定窗口，不能靠等权稀疏掩码或裁剪信号通过 |

所有结果不论通过与否均完整展示：各臂/状态的验证CE、IC/NW、累计净超额、策略绝对收益、成本、MDD、时间显存，并列FULL G1参照。交易与IC测试日期不同是标签可用性所致，必须披露，不能用IC日期裁剪交易。

分流规则：

- V失败：先解决明确实现/资产问题，只按同协议恢复受影响部分；披露失败轮，禁止将错误轮算正式模型失败。
- V通过但I/P/S任一失败：本次pilot未支持“A1优于全参数并更稳定”的联合命题；封存，不自动换A2/A3/LoRA或调lr。
- I/P/S通过、E失败：只有预测信息层证据，不能推荐交易替换；不自动优化组合规则。
- V/I/P/S/E全部通过：仅允许建议下一份seed101/102配对确认计划，本轮不自动补种子、不注册forward、更不宣称上线。
- 任一负结果只限“原生DualHead-only、当前数据/超参/预算”，不能扩大为所有受限适配无效。

两窗已被反复研究，t>2只作为预先写定的pilot筛选；原五臂方案及旧Q0~Q4不重新代入，不利用此次结果改历史结论。
