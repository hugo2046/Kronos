## 3. 冻结实验设计

实验编号 **MH1**；若 Debian 已有同名实验，预检停下报告命名冲突，不覆盖。

| 项目 | 固定值 |
|---|---|
| 主干 | G1 s100 tokenizer + predictor，全部冻结；维数从 `backbone.d_model` 读取，预期 832 |
| 输入 | 最近 90 个交易日的 OHLCVA，逐列窗口 z-score + clip 5，与 H1 一致；时间戳五列一致 |
| 训练池 | csi300 历史 PIT；不追加全 A 数据配置 |
| 训练标签覆盖 | 决策日起点 2014-01-02；所有标签终点 ≤ 2024-12-31；窗口不足自动跳过 |
| 验证标签覆盖 | 决策日 ≥ 2025-01-01；所有标签终点 ≤ 2025-06-30 |
| 期限 | 固定顺序 `(1, 5, 10, 20)` 个交易日；主期限索引 2 |
| 标签 | `close[t+k]/close[t]-1`，交易所日历定位，后复权口径与既有数据一致；不得用个股下一条记录代替下一交易日 |
| 共享头 | `LayerNorm(d) → Linear(d,128) → GELU → Linear(128,4)`；输入仅 `hidden[:, -1, :]`；无 dropout |
| S 单期限对照 | 四输出模型，只有 10 日输出参与损失，其余输出不进入任何评价 |
| M 多期限实验 | 同一四输出模型，四期限负 Pearson 损失等权平均 |
| 优化器 | AdamW，lr=3e-4，weight_decay=0.01，batch=128 同日截面无放回抽样 |
| 预算 | 每 epoch 2000 个更新，固定训练 15 epochs；两臂均不提前停止，保证相同更新预算 |
| 选点 | 仅验证段 10 日日均 RankIC 最大的 epoch；并列选最早，非有限值不能选；不看测试选择 epoch |
| 种子 | 42、43、44，S/M 成对同初始化、同日期顺序、同股票抽样，六次训练全部预注册 |
| 精度 | 首轮 FP32；不单臂切 AMP、量化或改变 batch；记录 CUDA/TF32/determinism 设置 |

这里固定 15 epochs 与 H1 的 patience=5 不同；两臂同时变更以匹配预算。历史 H1 只作背景参照，不能将 MH1−H1 差异归因为多期限监督。

**为何必须共享非线性层：** 冻结隐状态上接四个互不相干的线性头，辅助任务不会有效训练主任务表征。本计划用共享可训练 MLP；S 和 M 具有相同参数容量、同初始化，只改变监督范围。损失平均也改变主任务梯度权重，这是此联合训练方案的一部分，不事后搜索权重。

### 核心实现定义（在新包中实现，不修改旧包）

`mh1_multihorizon/heads.py` 的运算必须等价于：

```python
from __future__ import annotations

import torch
from torch import nn
from r1_objective.ic_loss import ic_loss


class MultiHorizonHead(nn.Module):
    """从最后历史隐状态读取四期限分数。

    :param d_model: 主干隐状态维数。
    """

    def __init__(self, d_model: int) -> None:
        super().__init__()
        self.net = nn.Sequential(
            nn.LayerNorm(d_model), nn.Linear(d_model, 128),
            nn.GELU(), nn.Linear(128, 4),
        )

    def forward(self, hidden: torch.Tensor) -> torch.Tensor:
        """计算排序分数。

        :param hidden: 形状 [B,T,D] 的历史隐状态。
        :returns: 按 1/5/10/20 日顺序排列的 [B,4] 分数。
        """
        return self.net(hidden[:, -1, :])


def horizon_loss(
    scores: torch.Tensor, labels: torch.Tensor, arm: str,
) -> torch.Tensor:
    """计算单日截面监督损失。

    :param scores: [B,4] 预测分数。
    :param labels: [B,4] 有限的累计收益标签。
    :param arm: S 为单期限，M 为联合期限。
    :returns: 标量负 Pearson 损失。
    :raises ValueError: 臂名非法时抛出。
    """
    if arm == "S":
        return ic_loss(scores[:, 2], labels[:, 2])
    if arm == "M":
        # 四项损失对应四个固定任务；数据构造已过滤退化截面。
        return torch.stack([
            ic_loss(scores[:, 0], labels[:, 0]),
            ic_loss(scores[:, 1], labels[:, 1]),
            ic_loss(scores[:, 2], labels[:, 2]),
            ic_loss(scores[:, 3], labels[:, 3]),
        ]).mean()
    raise ValueError(f"未知实验臂：{arm}")
```

## 4. 数据与泄漏门禁

实现 `mh1_multihorizon/data.py`，按实际交易日历构造四期限标签，不硬编码“12 月某日”截止日期。

1. 为每个 `(date, instrument)` 保留标签终点日期 `[4]`；先按交易所日历对齐，再定位未来价格。价格缺失保持 NaN，不能向前/向后填充；分母须有限且 >0。
2. **S/M 使用完全相同样本集合**：训练、验证均要求四期限标签完整且全部处于本段边界内，所有臂统一 purge 20 日。每日报告排除数；至少 128 只有效股票才进入训练，无放回抽样；抽样后任一期限标签方差为零则该批两臂共同跳过，使用相同确定性序列补足更新数。
3. PIT 资格只依据 t 日成员；不能用 t+20 仍在指数中作为资格。为监督标签完整性排除缺失终点须单独统计，披露由此带来的样本选择限制。
4. 每个特征窗口从 t 往回 90 个交易日，必须完整；均值和方差只能由这 90 日计算。股票之间、未来区间与标签不得参与输入归一化。
5. 标签可直接用 raw return（Pearson 对仿射变换不敏感）；S/M 同一口径，验证/评估始终使用原始收益的 Spearman。输出只能称分数，不报告收益幅度预测误差。
6. 不在完整 train+future 序列上一次 tokenize 后截取历史；每次编码严格只有样本历史窗口，避免 tokenizer 的时序运算访问未来。
7. 两个研究评价段：W3=`2025-07-01..2025-12-31`，W4=`2026-01-01..2026-07-24`；每段所有期限终点均须留在段内。按共同 20 日标签边界裁剪尾部，因此有效天数将少于旧 H1 的 126/134，不能沿用旧统计。
8. 推理股票资格只能由历史输入与 PIT 决定，不能看未来标签；IC 计算时再按标签可用性匹配样本。回测使用完整的历史可用信号集合，不能用未来标签完整掩码构造投资股票池。

## 6. 跑前判据与统计定义

**唯一主检验：M−S 的 10 日日截面 RankIC。** 1/5/20 日期限只作 M 的描述性诊断，不能挑最好期限判成功；S 的未受训辅助输出完全不评价。不把三种子当三倍独立时间样本。

对每个日期与每个种子，在 M/S 共同股票上分别算 RankIC，然后计算差值；三种子日均差构成一个时间序列 `delta_t = mean_seed(IC_M - IC_S)`。另构造 M 的三种子日均 IC。按 W3/W4 分别报告均值、日数和 NW(lag=9) t。

合并统计采用分段 HAC：设总有效天数 N、合并均值 mu，各段内中心化值 `z=x-mu`，
`V=[sum(z²)+2*sum(l=1..9,(1-l/10)*sum_within_window(z[t]*z[t-l]))]/N²`，
`t=mu/sqrt(V)`；不得把 W3 尾日与 W4 首日视为相邻交易日。意外缺失的日期也不得压缩成连续时间，按原交易日距离配对。V≤0 或数据不足则不可判。

本轮“值得另立前向验证”须同时满足：

1. M 的三种子日均 10 日 IC，在 W3、W4 两窗均 >0，且分段合并 NW t>2；
2. `delta_t` 在两窗均值均 >0，且分段合并 NW t>2；
3. 三个配对种子中至少两个种子的 M−S，在两个窗口均为正；
4. 全部数据与冻结底座门禁通过，六次训练按协议完成。

这是探索性筛选阈值，**不是纠正历史重复试验后的显著性声明**；不自动注册新臂、修改在位策略或读取 forward。通过时仅提出未来单独预注册的前向验证；不通过时封盘为“本协议下未支持多期限辅助监督带来稳健增益”，不能扩大成“所有多期限方法无效”。协议或实现错误则记“无效/未完成”，修复并披露后按同一协议重跑受影响部分，不能把错误轮当正式失败。

## 8. 跨机器交接步骤与一句话 handoff

交接顺序必须明确：**Mac 独立 worktree + 新分支 → 仅提交计划 → push 到 origin → 核对远端提交 → Debian fetch → 跟踪并切换同一分支 → 读取计划执行**。Mac 本地绝对路径不是 Debian 可访问地址，不能要求执行者读取未推送文档。

- 远端：`origin` = `git@github.com:hugo2046/Kronos.git`。
- 分支：`codex/timesfm-multihorizon`。
- Mac worktree：`/private/tmp/kronos-timesfm-multihorizon`；仅 Mac 使用。
- Debian：从该机已有 Kronos 仓库根目录运行，先确认 `git status --short` 无需保护的改动；如有改动不要直接切分支，使用新的独立 worktree。

首次在 Debian 建立本地跟踪分支：

```bash
git fetch origin codex/timesfm-multihorizon
git switch --track -c codex/timesfm-multihorizon origin/codex/timesfm-multihorizon
git rev-parse HEAD
git show HEAD:docs/TimesFM多期限监督实验计划_20260907.md
```

若 Debian 本地已有同名分支，先核对它确实是本任务的分支，再运行：

```bash
git fetch origin codex/timesfm-multihorizon
git switch codex/timesfm-multihorizon
git merge --ff-only origin/codex/timesfm-multihorizon
```

若工作区有其他任务改动，在核对目标路径不存在且同名分支未占用后，使用 `git worktree add --track -b codex/timesfm-multihorizon ../Kronos-timesfm-multihorizon origin/codex/timesfm-multihorizon` 建立 Debian 独立工作树；遇到已有分支/已占用工作树则定位现有工作树继续，不覆盖、不强制切换。

首次接手时，将拉取到的提交号与交接消息中的计划提交号核对；若远端已有后续实现提交，则确认该计划提交是 HEAD 的祖先。未找到计划文件就停止并报告拉取状态，不能按记忆重建计划。
