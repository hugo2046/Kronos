## 4. Git提交方式

仓库全局忽略`*.parquet`和`logs/`；本轮允许对**清单内确切文件**执行`git add -f -- <paths>`，或者仅为固定实验输出路径加精确例外。禁止`git add -f .`、取消全局忽略或把整个数据目录盲目提交。

- [ ] 先打印文件清单与大小；普通结果文件直接Git提交。单个文件>25 MiB则先记录大小与必要性，保留其余交付，不擅自拆分绕过限制；大权重/原始训练集后续另定LFS或artifact存储方案。本轮不安装LFS。
- [ ] 提交前查看`git diff --cached --stat`与完整文件名；确保没有软链、凭据、大权重、训练语料或其他任务文件；`git diff --check`通过。
- [ ] 输出报告 `docs/实验结果数据交付结果_实际日期.md`：文件数量/大小、已覆盖实验、验证输出、离线复算命令、缺失项与证据边界。
- [ ] commit并push至`origin/codex/experiment-data-export`，中文`feat:`/`docs:`/`test:`，正文含`Co-Authored-By: Hugo <shen.lan123@gmail.com>`；不merge。回传提交号与manifest路径。
- [ ] Mac随后拉取这个分支，即可用conda base的pandas/Qlib查看包内数据；导入R作为历史审计记录时须标`legacy_unverified`，不能改写为同期训练运行。
