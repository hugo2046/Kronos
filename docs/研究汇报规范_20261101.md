# Kronos 研究汇报规范

生效日期为2026-11-01，适用于本仓库模型研究与回测汇报。用户在具体任务中给出的新要求优先。生成报告前读取本文，并从现有记录核实当前采用方案的固定版本。

## 1. 先说清楚比较谁、改了什么

使用以下稳定称呼。

| 角色 | 名称 | 定义 |
|---|---|---|
| 主基准 | **原 G1** | 使用本土化微调后的 G1 tokenizer 与 predictor，经原生成式出口构造的选股组合。 |
| 当前已采纳方案 | **状态适配 MC40** | G1 最后两层加入单时点状态适配器。固定seed42和100各20条预测路径，两个流的均值信号等权合并。版本与指标见[采纳记录](https://github.com/hugo2046/Kronos/blob/master/docs/MC40模型采纳记录_20261101.md)。 |
| 同预算对照 | **G1_MC40** | 原 G1 以同样两个流各20条路径构造信号，不含状态适配器。比较采样配置的改动时列出。 |
| 本轮候选或控制 | **具体模型名** | 写明固定分支、提交、权重身份和输出定义，区分研究候选与已采纳方案。 |

报告首段用一句话说明研究问题、执行到的阶段及结论。紧接着说明改动发生在底座、预测头、采样汇总还是组合规则。微调后的原G1、冻结G1表示上的监督头、状态适配器和多流采样应分别说明。数字后的N或MC只代表路径配置，模型结构仍须写清楚。训练种子与推理随机流分别记录。确定性预测头的路径数写“不适用”，并报告实测推理耗时。

## 2. 收益报告默认交付 cumulative return 图

模型优化实验默认规划完整收益诊断，并在预算中预留生成累计收益曲线的资源。经济评估报告正文开头提供累计收益主图和核心指标表，聊天交付中直接展示主图，并附完整报告链接。

- 图中包含原 G1、当前已采纳参照和本轮已完成回测的候选。控制臂较多时另给完整附图，并明确主图所选对象。
- 主图口径为每日净收益的累计和 `cumsum(return - cost)`，与本项目既定研究主指标一致。图题或图注写明“扣费累计收益（每日净收益累加）”。
- 每个独立回测窗口分别绘制，标清实际起止日和百分比单位。多个面板优先使用相同纵轴刻度，必要的独立刻度需在图注明。
- 固定原G1为深灰蓝色、状态适配MC40为绿色，本轮主要候选为橙色。其他控制使用不同颜色或线型，图例保持全称。
- 使用完整已核验的逐日回测序列，曲线期末值须与表格一致。比较前核对日期、股票资格、成交时点、费用和组合规则。
- 原 G1 是主模型基准。指数曲线如有展示，单独标为“沪深300指数”，并与模型基准区分。
- 对收益差来源进行分析时，附候选减原G1的累计差额。回撤或其他诊断图根据研究问题增加。

## 3. 固定指标口径

每个窗口至少列出下表各项，并保留逐日数据及复算入口。

| 指标 | 默认计算方式 |
|---|---|
| 扣费累计收益 | `sum(r_t)`，其中 `r_t = return_t - cost_t`。这是窗口收益累计和，不能标成年化收益。 |
| 扣费复利收益 | `prod(1 + r_t) - 1`，与累计和分列。 |
| 年化夏普 | `sqrt(252) * mean(r_t) / std(r_t, ddof=1)`，默认无风险利率为0。零波动时标为不可计算。 |
| 最大回撤 | 初始净值为1，随后逐日复利，再算 `min(NAV / cummax(NAV) - 1)`，历史峰值包含初始净值。 |
| 总成本 | `sum(cost_t)`。 |
| 日均换手 | 对同一引擎报告的日换手字段求均值，并保留该字段定义。 |
| 相对原G1的变化 | 收益差使用百分点，同时列出候选与原G1的绝对值。 |

表下注明交易日数、股票日期有效格、是否扣费、持仓数量、换仓约束和成交时点。夏普、累计收益和回撤须从同一组日净收益计算。相对MC40的变化作为参照补充，不能替代原G1主对照。

若声称改进具有统计支持，给出适合重叠金融时序的检验或置信区间，并说明历史重复查看和多次尝试的影响。把“历史回测领先”和“获得独立验证”分别标注。

## 4. 分阶段报告真实完成情况

报告明确当前状态，例如待执行、工程检查通过、先导未通过、诊断性回测完成、历史收益门槛通过、已采纳或已封盘。

- 仅获授权进行先导检查，或候选尚未通过工程与数据完整性检查时，明确经济回测尚未运行。指标表中的收益写“未运行”，图例只列实际产生了完整回测数据的对象。
- 已训练候选通过工程与数据完整性检查，且完整历史数据和预算可用时，默认补齐真实收益曲线。即使先导保真未通过，也对冻结权重开展一轮**诊断性回测**。在计划或补充登记中写清这一目的，固定权重、窗口、组合及费用。原先导判定继续保留，诊断结果单独归档。
- 诊断图的标题或图注写明“诊断性回测，先导未通过”。其结果可以支持后续讨论，不能回填为原协议通过或自动改变采纳状态。
- 数据不足或计算受阻时，写明缺少哪项产物。已有基准图可作为背景，须明确候选曲线缺失的原因。

## 5. 一份报告的交付顺序

1. 一句话结论与阶段，明确是否超过原G1、相对MC40如何。
2. 模型身份和本轮改动，避免名称混淆。
3. 累计收益主图及每窗指标表。尚无经济回测时按第4节标注。
4. 必要的IC、保真、成本或个股诊断，解释观测到的差异。
5. 执行修订、验证结果、历史选择偏差和仍未完成的事项。
6. 复现入口，包含分支、固定提交、权重及输入哈希、逐日结果和命令。

文档按 `docs/功能名称_日期.md` 命名，图片使用仓库内相对链接。结果生成后更新[研究分支索引](https://github.com/hugo2046/Kronos/blob/master/docs/研究分支索引_20261101.md)，保留原始负结果和后续纠偏。聊天最终答复简要给出结论、主图、关键差值与报告入口。

## 6. 成交限制字段语义（2026-11-02纠偏）

当前DolphinDB后端的change是涨跌金额，不能与小数收益率阈值比较。价格限制统一使用经过核验的pctchange/100；在新纠偏入口中明确绑定执行口径ID、信号SHA与日报SHA。基准和候选必须同一执行口径。旧报告标为历史错误单位口径并链接纠偏记录，不能直接沿用旧收益数字。保留统一9.5%日频阈值属于研究简化，并非全部真实交易规则。见[完整纠偏报告](成交限制单位纠偏与冻结方案复核报告_20261102.md)。
