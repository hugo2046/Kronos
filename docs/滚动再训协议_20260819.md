# 滚动再训协议（G1 版本更迭规则）· 冻结文档

> 日期：2026-08-19
> 性质：运营协议——冻结"什么时候再训、怎么训、怎么验收、怎么切换"，杜绝届时裁量。
> 生效条件：2026-11 forward 结算走**滚动分支**（`forward结算计划_20260818.md` §6）；
> 走关闭分支则本协议作废。
> 判读框架：采用 2026-08-19 修正版噪声感知框架（N50 封盘的方法论遗产）——
> 窗口 AER 标准误由日度 TE 推导（134 日窗 ≈ ±26pp），比较类结论只认超噪声底的
> 差距；冻结判据是**决策规则**（预承诺装置），不是统计发现。

## 1. 再训触发（冻结）

- **定期无条件**：每年 1 月第二个交易周执行（首次 2027-01，若届时已进入滚动期）；
- **禁止条件触发**："最近表现不好所以提前重训" = 裁量 = 禁止。日历是唯一触发器。

## 2. 再训配方（逐字冻结 = G1 配方 + 已验收的纵深防御）

| 项 | 值 |
|---|---|
| 起点 | 官方 Kronos-base + Tokenizer-base（每次从官方底座完整重跑，不做版本间续训——防漂移积累，保证任意版本可独立复现） |
| 语料 | ashares 半年采样 PIT 并集；起点固定 2014-01-02，**终点滚动至上年 12-31**；DDB 清洁源 + 交易日历内连接过滤 + "所有日期 ∈ 日历"断言（G4 防御纳入） |
| 切分 | train 至上年 12-31；val = 当年 1 月前的最后 6 个月？否——**val = 上年 7-01~12-31**（最新半年做早停，与 G1 的"train 尾接 val"结构同构） |
| 协议 | 两阶段（tokenizer→predictor）、epochs=15、batch=50、每 epoch 2000 步、lr 2e-4/4e-5——与 `finetune_suite/` 逐字一致 |
| 种子 | 100/101/102 三种子完整重训（单种子版本禁止上岗） |
| 健全性门禁 | tokenizer val 须单调降形态（异常则停线调查）；warm-start 等价类测试、DuckDB 对拍、全仓测试通过；训练全程只看 train/val |

**任何超参/语料构成/种子数的变更 = 新研究 = 另立预注册计划**，不得借"年度例行"夹带。

## 3. 验收门禁（修正版 Q3 框架的落地）

比较窗 = 新版本训练截止后、验收时点前的全部可用数据（必然半污染，如实标注）。
按噪声框架，"新版是否更好"在 ±26pp 噪声底内**不可判**——因此门禁不设"新胜旧"：

- **默认换新**：语料新鲜度是全项目唯一被验证的正向杠杆（F0→F1→G1 链），年度再训
  多喂一年语料，先验支持新版——无需证明"更好"即可上岗；
- **灾难否决（唯一拦截条款）**：新版三种子中位在比较窗 AER(等权) 落后在位版本中位
  **超过 26pp（噪声底）** → 拦下新版、保留旧版，升级为事件调查（另立文档），
  禁止当场调参重训；
- 噪声底内的任何差距（无论方向）：如实记录，不影响换新，措辞"不可判"。

## 4. 切换机制（冻结）

1. 新版通过 §3 → 登记表**新增列**（`G1v<年份>_sXXX_*`），旧版列**并行登记 ≥60 个
   交易日**（双跑过渡期，供事后对照），之后旧版停止登记、历史列与权重永久封存；
2. C1/C2/C3 等组合规则**版本绑定**当前在位模型列；版本切换时按本协议模板另发
   规则 v(N+1) 冻结文档（判据原文继承、仅列名更替），旧规则的 forward 记录封存不删；
3. 切换事件写入结果文档：配方哈希、语料统计、三种子 val 表、比较窗全表
  （决策栏 = §3 代入；证据栏 = 噪声折扣后评估，双轨措辞）。

## 5. 纪律

- 本协议冻结后，再训的每一步都应当是**机械的**——若执行中出现任何需要"判断"的
  时刻，说明协议有洞：停下、披露、修订协议（修订须在下一轮再训开始前公开提交，
  不得在训练中途改规则）；
- 验收比较不做子期挑选、不做变体挑选（判据只在 mean 中位）；
- forward 零判读、登记只写不读等既有条款全部沿用；
