# G1周期残差分支账户舍入比较修正

阶段：root已完成A模型24/24保真检查，但固定GPU预算门禁不通过（预计剩余47426.96秒，加已用804.92秒超过12小时），未签A_gate、未启动正式训练。随后CPU参照账户跨进程bitwise比较因聚合浮点舍入停止。本次只修复比较层，不改变模型、信号、数据、账户引擎、研究配置或预算。

## 证据与固定容差

依据OUT/root_baseline_roundoff_diagnostic.json，日期、股票、行数一致，持仓数量/价格、全部成交quantity/price/value/cost、逐股pnl/cost逐值相同。观察到的最大聚合差异：return约8.36e-16、turnover约1.83e-15、NAV约7.45e-8元、cash约1.49e-8元。因此跨进程聚合结果不能要求bitwise，更不能一律放宽所有数值字段。

root明确授权如下字段schema，`compare_account_frame(kind, actual, expected)`严格执行：

| 表 | exact字段 | 绝对容差1e-12 | 绝对容差1e-6元 |
|---|---|---|---|
| report | 日期索引、结构、dtype | return、cost（费用率）、bench、turnover | 无 |
| positions | date、instrument、start_amount、end_amount、start_price、end_price | start_weight、end_weight | previous_nav、nav |
| trades | date、instrument、quantity、price、value、cost（成交原费用） | 无 | previous_nav |
| balances | date | 无 | previous_nav、nav、start_cash、end_cash、cash_delay |
| stock_daily_contributions | date、instrument、pnl、cost（逐股原费用） | gross_contribution、cost_contribution、net_contribution | previous_nav |

所有表先核对完整字段集合、列顺序、索引与dtype；明细按已登记业务键稳定排序后比较，日报日期顺序保持原样。相对容差rtol固定0。未知表、未知字段、缺失或重复列不默认宽容；聚合字段非有限值拒绝。数量、价格、成交费用与原始pnl的微小改动也拒绝。

helper返回每字段`max_abs`、`atol`及是否逐值相等，并明确标记`fieldwise_absolute_tolerance_not_bitwise`。结果写入A_accounts与最终economic_result的parity，可供报告和独立审计读取；不再把整体对账成功称为bitwise相等。
