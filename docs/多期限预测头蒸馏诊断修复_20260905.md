## #1 教师 eval（成立 · 高严重度 · 影响 v1 教师分片有效性）

- **取证**：G1 predictor 配置 `ffn_dropout_p=0.2 / resid_dropout_p=0.2`
  （`finetune_predictor_g1/checkpoints/best_model/config.json`）；
  `cli._load_predictor` 装载链 `from_pretrained → .to(device) → KronosPredictor`
  **从未调用 `.eval()`**——PyTorch 模块构造后默认 train 态，dropout 生效。
- **影响**：v1 全部教师目标与 3 组 replica 在 20% dropout 噪声下生成——
  R（=0.0220）含 dropout 噪声（真实采样噪声 ≤ 该值），且目标系统性偏离
  eval 态 G1 生成分布。**v1 门禁 FAIL 的归因（"本规格蒸馏保真不足"）因此
  存在混杂，结论降级为 provisional**；封盘数字保留不动，v1.1 用干净教师
  重评（见 v1.1 方案）。
- **修复**：`teacher.ensure_teacher_eval(predictor)`（model+tokenizer 强制
  eval 并断言）；`_load_predictor` 装载后调用；`TeacherRunner.identity`
  增加 `"model_eval": True`——**v1 分片（无该字段）与新代码天然隔离，
  不可混用**。
- **回归**：`test_ensure_teacher_eval_forces_eval`、
  `test_teacher_identity_carries_model_eval`（v1 旧身份拒绝复用）。

## #2 D2 损失比较（成立 · 中严重度 · v1 未触发）

- **取证**：`cli._eval_fidelity` 原实现
  `best_d0=min(val_loss)` vs `best_d1=min(val_loss)`——D0 的 `val_loss`
  是 **val_d**，D1 的是 **val_task**，跨口径比较违反 §8.3
  「D1 在验证 S+0.05I 优于 D0」。
- **影响**：v1 中 `d2_unlocked=False`（两臂未齐，条件未评估到该分支），
  对 v1 结果零影响；属潜伏缺陷。
- **修复**：抽出纯函数 `evaluate.d2_unlock_condition(d0_history,
  d1_history, d0_fidelity, d1_fidelity)`——两臂统一取 `min(val_task)`
  比较；CLI 改调该函数，判定细节（best val_task、三条件）写入
  fidelity summary。
- **回归**：`test_d2_unlock_compares_val_task_not_val_d`
  （D0 val_d=0.01 极小也不参与比较；三条件独立生效）。

## #3 LoRA device/dtype（成立 · 中严重度 · v1 未触发）

- **取证**：`backbone.LoRALinear.__init__` 原实现 `nn.Linear(in, rank)`
  不带 device/dtype——默认 CPU/float32；D2 底座在 CUDA 上，注入即产生
  CPU 参数，优化器/反传设备失配。
- **影响**：D2 从未运行，v1 零影响；潜伏缺陷。
- **修复**：A/B 以 `base.weight.device/dtype` 构造；前向不发生 dtype 降级。
- **回归**：`test_lora_follows_base_dtype_and_device`（float64 基座 →
  A/B float64、输出 float64）。

## #4 缓存身份（成立 · 中严重度 · v1 事实无混用，机制缺失）

- **取证**：三处——
  (a) `cli._load_manifest` 取 `sorted(glob)[-1]` 按字典序选清单，**不校验
  protocol**；(b) `DayManifest.load` 不重算内容 hash（静默损坏不可检）；
  (c) `cli._targets/_teacher_array_for` 用 `TeacherRunner.__new__` 直通装载，
  **跳过全部身份核验**（protocol/清单 hash/replicas/predict_len/权重）。
- **影响**：v1 运行时权重未变、目录唯一，事实未混用；但协议漂移或权重
  更换后旧分片可被静默复用。
- **修复**：`_load_manifest(profile, split, cfg)` 按 manifest.json 的
  protocol/profile/split 过滤（无匹配显式报错）+ `load(verify=True)` 重算
  内容 hash；新增 `TeacherRunner.load_verified(...)` 类方法逐字段核验
  （含 `expected_weight_hash`——train 命令传当前 G1 权重指纹，闭环权重
  漂移检测）；两处 `__new__` 全部替换。
- **回归**：`test_manifest_load_verify_detects_tamper`、
  `test_load_manifest_protocol_filter`、
  `test_teacher_load_verified_rejects_mismatch`。

## #5 阶段门禁（成立 · 低严重度 · v1 未触发）

- **取证**：(a) `_require_d2_gate(profile)` 不校验 seed——seed42 的门禁
  文件可解锁 seed43 的 D2；(b) D1/S-long/D1-cont 缺前置结果时裸抛
  FileNotFoundError，非显式门禁语义。
- **修复**：`_require_d2_gate(profile, seed)` 比对 summary.seed；
  `_require_arm_ready(profile, arm, seed)` 显式前置链
  （D1←D0、D2←D1、S-long←D0+D1、D1-cont←D1+D2），cmd_train 入口统一调用。
- **回归**：`test_d2_gate_seed_must_match`、`test_arm_prerequisites_enforced`。
